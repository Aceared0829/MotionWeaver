摘要

本报告记录 MotionWeaver 的技术现状：一个把离散姿态 Token用于游戏角色全身姿态生成的实验系统， 以及支撑它的数据管线。系统在 NVIDIA GR00T-WholeBodyControl / MotionBricks 的架构基础上裁剪， 以 VQ-VAE 把逐帧骨架姿态压缩为离散码，再以 Pose Token 主干在给定前 4 帧历史姿态与一条独立的 Actor 世界轨迹的条件下预测未来姿态 Token，最后经解码器还原为世界空间骨架。 数据侧，我们完成了 1,722 段 UE 动画（79 骨、30 FPS）与 71,132 条 SOMA 通用动作（78 节点、120.0048 FPS）的 接入与处理，并把处理吞吐提高到约 1.69–1.80 倍，且输出逐数组等价。 训练侧在单卡 A800 上从零训练 20,000 步，固定验证口径下的掩码姿态 Token 交叉熵由 2,000 步的 1.862 nats 降至 1.454 nats（−21.9%）。 但本报告同样记录失败：在 3 条同轨迹对照片段中，Walk 的世界关节 RMSE 由基线 6.72 cm 改善至 6.03 cm， 而 Run（7.36 → 12.00 cm）与 Crouch（5.87 → 8.25 cm）明显退化；接触期脚滑整体仍显著高于来源动作； 换用另录的 CMC 轨迹后，90° 转向只改变 Actor 局部关节姿态 0.50 cm，且蹲伏状态未被模型响应。 我们据此明确当前系统的能力边界：姿态 Token 预测的学习信号确实在改善， 但从「Token 交叉熵下降」到「玩家可操控时姿态与位移一致」之间仍缺一条已验收的链路。

Abstract. This report documents MotionWeaver, an experimental system that generates full-body character poses through discrete pose tokens, together with the data pipeline behind it. Built on the NVIDIA GR00T-WholeBodyControl / MotionBricks architecture, a frozen VQ-VAE quantizes per-frame skeletons into codebook indices; a pose-token backbone then predicts future tokens from four history frames and an independent actor world trajectory. On the data side we ingest 1,722 Unreal Engine clips (79 bones, 30 FPS) and 71,132 SOMA clips (78 joints, 120.0048 FPS), and improve processing throughput by 1.69–1.80x with array-level equivalence. A 20,000-step training run on a single A800 reduces masked pose-token cross-entropy on a frozen validation split from 1.862 to 1.454 nats (-21.9%). We also report failures: on three same-trajectory clips, walk improves (6.72 to 6.03 cm joint RMSE) while run (7.36 to 12.00 cm) and crouch (5.87 to 8.25 cm) degrade; contact-phase foot sliding remains far above the source motion; and replacing the trajectory with a recorded CMC capture changes local joint poses by only 0.50 cm under a 90 degree turn, with crouch state unobserved. We therefore state the capability boundary explicitly rather than inferring playable quality from a falling token loss.

形式上，本报告把它定义为一个以离散姿态码为目标的掩码条件预测问题（§3）： 给定 $h$ 帧历史姿态与一条外部 Actor 轨迹，最大化未来姿态码的对数似然（式 3.7）。 损失函数、评测指标与硬约束投影都写成可复核的显式定义， 使每个数字都能追溯到它对应的数学对象（§5、§6）。

1  引言

游戏角色的全身动画长期由动画状态机、混合空间与 Motion Matching 等检索式方法主导。这类方法在 确定性与可调试性上有明显优势，但其表现力被资产库的覆盖范围所限制：玩家做出资产库没有的组合动作时， 系统只能退回到不匹配的片段或生硬的混合。近年来，学习式动作生成在动作补间、文本驱动动作以及 物理角色控制上取得进展，使「由条件实时合成姿态」成为一个现实的工程选项。

MotionWeaver 的目标是一个具体的工程问题：在 Unreal Engine 中，让模型根据玩家控制器的运动状态 与历史姿态，持续生成与该位移一致的全身姿态。我们把世界位移（Root）的权威留给引擎的运动组件 （CMC / Mover），模型只负责生成 Actor 相对的身体姿态。这个分工不是架构偏好，而是把 「碰撞、网络权威、可回滚的位移」留在引擎侧，把「姿态合理性」交给模型。

技术路线上我们沿用 NVIDIA GR00T-WholeBodyControl 仓库中 MotionBricks 的做法：先把动作离散化为 姿态 Token，再在 Token 空间做序列预测。离散化的好处是模型只需预测有限码本上的索引，误差不会像 逐关节回归那样直接累积到厘米级的关节位置上；代价是量化误差与解码器条件的耦合，这一点在 §7.6 的 oracle 诊断里被量化了。

本报告的三点贡献是：

  • 一条可追溯的双来源数据管线。UE 导出与 SOMA 通用动作在统一的 78 节点目标骨架上汇合， 每条 clip 带内容哈希、帧率分组与显式边界声明（§3）。
  • 一组可复现的固定口径评测。冻结验证集、冻结划分、冻结随机种子，同时报告 Token 级指标、世界姿态指标、接触指标与控制器条件探针（§6、§7）。
  • 一份如实的能力边界陈述。我们把退化案例、缺失条件以及「哪些数字不能当成在线能力」 逐条写进报告与附录（§8）。
阅读方式 —— 本报告刻意把「训练指标改善」与「产品可用」分成两件事陈述。 §7.1–§7.2 是学习信号，§7.3–§7.5 是离线质量，§7.6 是上限诊断，§8 是缺陷清单。 任何一节单独拿出来都不足以支撑「模型可用」的结论。

2  相关工作

2.1  离散动作表示与生成

VQ-VAE 把连续信号映射到有限码本上的离散索引，是离散生成式建模的基础构件[3]。 在图像领域，VQGAN 展示了「离散 Token + 自回归先验」的有效性[4]； 在人体动作领域，T2M-GPT[7] 与 MoMask[8] 沿同一思路把 HumanML3D[5] 的动作序列压缩为 Token 再做生成； 扩散模型路线则由 MDM[6] 等代表。MotionWeaver 属于前者， 但把 Token 的预测任务限定为「短历史 + 已知外部轨迹 → 未来姿态」， 而不是「文本 → 整段动作」。

2.2  目标驱动的角色动画

面向目标（trajectory / keyframe / contact）的动画方法大致分两支。 程序化一侧以 Motion Matching 为代表，把当前姿态与目标特征放到同一空间里做最近邻检索 [9]，并用 Learned Motion Matching 把检索网络化[10]。 学习一侧用相位、VAE 或扩散模型生成中间姿态：Local Motion Phases 用相位变量组织多接触动作 [11]，Motion VAE 控制器把状态与潜变量一起驱动角色[12]， Robust Motion In-betweening 用带噪插值策略学习关键帧之间的补间[13]， 扩散式方法进一步放宽了关键帧的约束形式[14]。

MotionWeaver 的位置介于两支之间：它借用学习式生成来表达资产库之外的姿态， 但把确定性约束（步幅、朝向、脚部贴地）交给 Warping 与 IK 这类程序化模块（§5.4）， 并用阈值化的回退路径保证失败可控。

2.3  与上游项目的关系

本仓库基于 [1, 2] 的架构与参考实现，保留了 VQ-VAE 分词器、 姿态主干与 G1 参考演示；面向 UE 的裁剪包括：79 骨（后为 78 节点 SOMA 骨架）的姿态表示、 独立 Actor Root sidecar、玩家状态条件接口，以及 Windows 本地推理与导出工具。 上游权重与本仓库训练权重严格区分，报告中的任何指标都来自本仓库自己的检查点。

3  问题形式化

本节把「由玩家控制状态生成全身姿态」写成显式优化问题。公式里出现的每个符号都在下表定义， 后续所有损失、指标与约束只用这些符号。这样做不是因为偏好形式化，而是为了修掉我们在 §8.3 记录的三次误判——它们的共同点是同一个符号在不同章节指代了不同对象。

时间与索引
$T,\;h$窗口帧数与历史帧数。本系统 $T=24$，$h=4$（30 FPS 下 $h$ 恰为 133 ms）。
$t,\ \ell$帧索引 $t\in\{1,\dots,T\}$；Token 索引 $\ell\in\{1,\dots,L\}$。
骨架与位姿
$J$关节数。UE 侧 $J=79$（骨），SOMA 侧 $J=78$（节点）。

$\mathbf{R}_t^{j}\in SO(3)$第 $t$ 帧第 $j$ 关节的世界旋转（单位四元数或 $3\times3$ 正交阵）。
$\mathbf{q}_t\in\R^{7}$第 $t$ 帧 Actor 世界轨迹位姿 $(x,y,z,\,q_x,q_y,q_z,q_w)$，Y 轴向上。
$\mathbf{b}_t^{j}$Actor 相对的身体位姿，$\mathbf{b}_t^{j}=\mathbf{q}_t^{-1}\odot(\mathbf{p}_t^{j},\mathbf{R}_t^{j})$。

3.1  姿态的离散化

编码器 $E_\phi$ 把一段身体位姿压成 $L$ 个潜向量，解码器 $D_\psi$ 在外部条件下还原：

(3.1)\[\mathbf{u}_{1:L}=E_\phi\big(\mathbf{b}_{1:T}\big),\qquad \hat{\mathbf{b}}_{1:T}=D_\psi\big(\hat{\mathbf{u}}_{1:L},\ \mathbf{c}^{\text{ext}}\big).\]

量化器把每个 $\mathbf{u}_\ell$ 吸附到码本中最近的一项：

(3.2)\[z_\ell=\arg\min_{k\in\{1,\dots,K\}}\big\|\mathbf{u}_\ell-\mathbf{e}_k\big\|_2, \qquad \hat{\mathbf{u}}_\ell=\mathbf{e}_{z_\ell}.\]

码本由多头 EMA 更新而非梯度优化。因此主干训练时量化步是冻结的： 主干看到的 $z_\ell$ 是常量标签，学习问题退化为干净的多类分类（§5.2）。 这一点很关键——它使「Token 交叉熵」可以被单独报告，而不与重建误差混为一谈。

3.2  条件预测任务

给定 $h$ 帧历史身体姿态与未来 $T$ 帧外部 Actor 轨迹，预测未来姿态码：

(3.3)\[p_\theta\big(Z\mid\mathbf{b}_{1:h},\mathbf{q}_{h+1:h+T}\big) =\prod_{t=1}^{T}p_\theta\big(z_t\mid\mathbf{b}_{1:h},\ \mathbf{q}_{h+1:h+T},\ z_{\lt t}\big).\]

条件里不含 $\mathbf{b}_{h+1:h+T}$：未来真实姿态只作为监督目标。 另一条更隐蔽的约束是 $\mathbf{q}_{h+1:h+T}$ 在推理期不可得——游戏里它只能来自 CMC/Mover 或规划器，不可能等于真值。因此凡是使用 $\mathbf{q}^{\text{true}}$ 的数字都只在 「配对教师轨迹」口径下成立，这一点在 §5.2 与 §8.2 各强调一次。

3.3  训练目标

采用掩码建模目标：随机遮住比例 $r$ 的姿态码，只对被遮住的位置计损失，

(3.4)\[\mathcal{L}_{\text{token}}(\theta) =-\frac{1}{|\mathcal{M}|}\sum_{t\in\mathcal{M}} \log p_\theta\big(z_t\mid\mathbf{b}_{1:h},\ \mathbf{q}_{h+1:h+T},\ Z_{\setminus\mathcal{M}}\big).\]

单位是 nats（自然对数），这也是全文所有「Token CE」的口径。 VQ-VAE 一侧的损失（本报告中被冻结，不参与主干训练）为

(3.5)\[\mathcal{L}_{\text{vq}} =\big\|\mathbf{b}_{1:T}-\hat{\mathbf{b}}_{1:T}\big\|_2^{2} +\big\|\mathrm{sg}[\mathbf{u}]-\hat{\mathbf{u}}\big\|_2^{2} +\beta\big\|\mathbf{u}-\mathrm{sg}[\hat{\mathbf{u}}]\big\|_2^{2},\]

三项依次是重建、码本与承诺，$\mathrm{sg}[\cdot]$ 为停止梯度算子。 它们的分工是：重建管解码质量，码本管码本更新，承诺管编码器不要频繁跳到别的码。

3.4  接触约束与它的去向

若记脚部接触指示为 $c_t^{\text{foot}}\in\{0,1\}$，接触期的理想约束是

(3.6)\[\Big\|\tfrac{\d}{\d t}\mathbf{p}_t^{\text{foot}}\Big\|_2\le\epsilon \qquad\text{当}\quad c_t^{\text{foot}}=1.\]

式 (3.6) 不进入 $\mathcal{L}_{\text{token}}$。我们把脚部约束交给输出端的 Foot Lock 与 Foot IK（§5.4），模型只负责姿态合理性。§7.3 报告的 0.78–0.88 m/s 就是式 (3.6) 未被满足的量化形式。

4  数据管线

4.1  两个来源，一套目标骨架

训练数据来自两条互不相同的管道。第一条是项目自有 UE 动画：从 AnimSequence 导出骨架与逐帧姿态，得到 1,722 段 79 骨、30 FPS、954 维的动作， 划分 train 1,355 / validation 189 / test 178，三个分区的动作家族（asset family）两两交集为 0。 这条管道的关键产物是一份独立的 Actor Root sidecar：每段附一条 [frames, 7] 的米制 Y-up 世界轨迹（xyz + xyzw 四元数），使「身体姿态」与「世界位移」在数据层就分离开。

第二条是SOMA / BONES-SEED 通用动作库：71,132 条非镜像记录、62,301,201 帧， 最短 69 帧、最长 21,617 帧、中位 685 帧，来源声明帧率约 120.0048 FPS。 这套数据使用 78 节点的 soma_uniform_v1 固定骨架，含手指与面部关节。

两条来源的骨架不同（79 骨 vs 78 节点），但都汇入同一个目标骨架定义。 处理时遵循一条硬约束：原始数据永不改写。派生表示一律写入新批次目录， 并以内容哈希绑定；回读校验的门槛是 Root/身体重合成误差不超过 1e-9 m， 实测四轮试点的最大误差为 8.88e-15 m。

4.3  Root 的离线表示：代理而非真值

SOMA 的 Root 节点在多数片段中是静止的，真实运动合并在 Hips 上。 因此训练用的 root_track 是一条从 Hips 派生的代理轨迹：水平位置与朝向取自 Hips， 垂直高度全部保留在身体姿态里。该代理可逆（回读可完全恢复录制位置）， 但它不是场景中观测到的 Actor Root，输出中显式标注 root_status = offline_proxy_not_observed_actor_root。

形式化地，记 Hips 世界位置为 $\mathbf{h}_t=(h_x,h_y,h_z)$，则代理 Root 与身体位姿定义为

(4.1)\[\mathbf{q}_t^{\text{proxy}}=\big(h_x,\,0,\,h_z,\ \psi_t\big),\qquad \tilde{\mathbf{b}}_t^{j}=R_y(\psi_t)^{-1}\big(\mathbf{p}_t^{j}-(h_x,0,h_z)\big),\]

其中 $\psi_t$ 为左右髋形成的前向偏航角。注意竖直分量 $h_y$ 留在身体位姿里， 因此回读可精确恢复录制位置：

(4.2)\[\mathbf{p}_t^{j}=R_y(\psi_t)\,\tilde{\mathbf{b}}_t^{j}+(h_x,0,h_z), \qquad \max_{j,t}\big\|\hat{\mathbf{p}}_t^{j}-\mathbf{p}_t^{j}\big\|_\infty\le 10^{-9}\ \text{m}.\]

实测四轮试点的最大重合成误差为 $8.88\times10^{-15}$ m，比门槛低五个数量级。 但必须先说清：这是离线代理，不是场景观测到的 Actor Root。

这个区分不是学术洁癖。2026-09-28 的实验中，早期把 motion_*.npy 里的 5 维 root（实为 Actor 相对的骨盆特征）误当作 CMC Root 使用， 会直接污染「模型能否跟随控制器轨迹」的结论；发现问题后改为逐片段重建 sidecar， 并用「复跑所得 1,722 个文件与上传内容逐字节一致」来确认修复。

4.4  接触候选：区分「未知」与「非接触」

脚部接触是逐帧四值状态：-1 unknown、0 noncontact_candidate、 1 contact_candidate，另有手部始终为未知。规则是几何与运动学的联合判据： 脚使用踝/趾代理点在完整录制空间的速度（不是骨盆相对速度）， 并要求持续时间、进出速度与高度变化同时满足；每只脚可保留多个稳定代理高度， 避免把高台上的脚因远离全局最低点而一律判为腾空。

必须强调的是：contact_known_mask 只表示「有候选值」， 不表示人工确认或传感器真值。本报告中的所有「接触脚速」指标都建立在 这层启发式标签上，用来做相对比较，不作为绝对物理量。

4.5  双帧率：用 Token 时间粒度对齐，而不是用帧数

UE 来源是 30 FPS，SOMA 主库是 120.0048 FPS。直接把两者混进同一个 batch 会破坏 Token 的时间语义： 同一个 down_t 在 120 FPS 下是 133 ms，在 30 FPS 下却变成 533 ms。 我们的做法是让每个 Token 覆盖的时间一致。设基准帧率 $f_0=120.0048$、 编码器降采样层数 $\delta$（即 down_t），则单个 Token 覆盖

(4.3)\[\tau(f,\delta)=\frac{2^{\delta}}{f}\quad\text{秒},\]

要让两种帧率语义等价，只需 $\tau(f_1,\delta_1)=\tau(f_0,\delta_0)$，即

(4.4)\[\delta(f)=\delta_0-\log_2\frac{f_0}{f} =\delta_0-\mathrm{round}\!\Big(\log_2\tfrac{f_0}{f}\Big).\]

代入 $f_0=120.0048$、$f=30$ 得 $\delta(f)=\delta_0-2$。具体取值：

down_t(fps) = down_t(base) - round(log2(base_fps / fps))      base_fps = 120.0048

场景 A（常规移动，窗口 0.4 s）
    120fps + down_t=4  ->  16 帧/Token  =  133.33 ms
     30fps + down_t=2  ->   4 帧/Token  =  133.33 ms

场景 B/C（大姿态转换 / 跑酷，0.6 s）

5.1  两段式：分词器 + 姿态主干

5.2  条件与监督的边界

一个训练样本包含三类信息，其可见性被严格区分：

  • 可见条件：前 4 帧真实姿态（作为历史），以及由外部提供的未来 Actor 轨迹。
  • 不可见条件：未来真实姿态。它只以 Token 目标的形式出现在损失里。
  • 训练期可见、推理期不可得：来源动作的未来 Actor Root。它作为「配对轨迹教师」参与训练， 但在真实游戏里，未来的轨迹只能由 CMC/Mover 或规划器给出，不可能等于真值。

第三点是本报告所有对照实验的解读前提。凡是标注「配对教师轨迹」的结果， 都只说明模型在该轨迹下能生成什么，不说明它在玩家控制下能生成什么。 为此我们另设了一组使用「另录 CMC 轨迹」的探针（§7.5）。

5.3  为什么是 4 帧历史

历史长度决定了推理延迟的下界与信息的充分性。本项目早期的轻量基线 ReferenceGuidedPose（约 310 万参数，GRU 历史编码加 3 层 Transformer）使用 24 帧历史； MotionWeaver 的 actor_root_history4_compact_v1 只给 4 帧。 这是一个刻意的取舍：4 帧 @30 FPS 是 133 ms，恰好等于一个重规划步长， 使「上一窗口的输出立即成为下一窗口的历史」成为可能。 代价是模型获得的动力学信息更少，这可能是 §7.3 中 Run 退化的原因之一， 但那只是假设：本报告没有做「只改历史长度」的受控实验来证明它。

5.5  硬参考姿态的等式约束投影

除纯生成路径外，系统还支持「给定若干时刻的硬参考姿态」这一条件形式。 设生成输出为 $\{\mathbf{o}_t\}_{t=1}^{T}$（局部平移或旋转向量）， 参考帧集合 $\mathcal{K}$ 上给定目标 $\mathbf{r}_k^{\star}$。我们求一个修正量 $\{\Delta_t\}$：

(5.1)\[\min_{\{\Delta_t\}}\; \sum_{t=1}^{T}\|\Delta_t\|_2^{2} +\lambda\sum_{t=2}^{T-1}\big\|\Delta_{t+1}-2\Delta_t+\Delta_{t-1}\big\|_2^{2} \quad\text{s.t.}\quad \mathbf{o}_k+\Delta_k=\mathbf{r}_k^{\star},\ \ \forall k\in\mathcal{K}.\]

第一项是最小范数（改动尽量小），第二项是二阶差分（改动尽量平滑，抑制抽搐）， 等式约束保证参考帧精确到位。这是一个带等式约束的二次规划， 用拉格朗日乘子求解，规模为 $|\mathcal{K}|$ 个乘子：

(5.2)\[\begin{bmatrix} A & C^{\mathsf{T}}\\ C & 0\end{bmatrix} \begin{bmatrix}\Delta\\ \boldsymbol{\mu}\end{bmatrix} =\begin{bmatrix}\mathbf{0}\\ \mathbf{r}^{\star}-\mathbf{o}\end{bmatrix},\]

其中 $A=I+\lambda D^{\mathsf{T}}D$，$D$ 为二阶差分矩阵，$C$ 为在 $\mathcal{K}$ 上取值的指示矩阵 （故 $C\Delta=\mathbf{r}^{\star}-\mathbf{o}$）。解出后 $\Delta=A^{-1}(I-C^{\mathsf{T}}(CA^{-1}C^{\mathsf{T}})^{-1}C)\,(\mathbf{r}^{\star}-\mathbf{o})$， 与参考相距 8 帧以上的位置 $\Delta_t$ 自然为零——这是 $D^{\mathsf{T}}D$ 的局部支撑带来的， 不是额外加的阈值。旋转侧对 $SO(3)$ 使用主值旋转向量再以四元数组合回位姿， 避免在 $\pi$ 附近出现分支跳变。

在一个用户手选 6 帧的跑酷翻越片段上（源帧 32/34/44/52/56/59），平均关节误差由 11.322 cm 降至 6.903 cm，加速度误差由 4.008 升至 4.186 cm/帧²。参考帧位置误差为数值零 （最大局部旋转误差小于 0.000003°），但这是约束构造的结果，不是模型预测精度。 平滑版本明显优于直接覆盖（后者加速度误差恶化到 9.428），却仍不如软输出平滑， 因此不能声称已消除抽搐。该路径没有速度等式、接触、碰撞或关节限位保证。

6  实验设置

6.1  冻结的评测口径

为了在多次训练之间做可比，我们固定了三件事：

  • 验证集：48 条片段（Walk / Run / Crouch 各 16 条），共 2,608 个监督 Token， 随机种子 1701，manifest 与 sidecar 哈希两次记录完全相同。
  • 采样协议：每条片段使用前 4 帧来源姿态作为历史，生成其后 24 帧； 不输入任何未来真实姿态。
  • 对照基线：ReferenceGuidedPose 在同一条来源 Actor Root 下运行， 共享同一批测试片段。两者历史长度不同（24 vs 4 帧）， 因此这是产品路线对照，不是「只改架构」的严格消融。

6.2  指标定义

所有指标写成公式后，"为什么 Run 的 Token CE 降了 15% 而世界误差升了 4.6 cm"这类问题 才有明确的讨论对象：式 (6.1) 与式 (6.2) 衡量的根本不是同一个空间。设测试片段集合为 $\mathcal{S}$，每段评估未来 $T=24$ 帧。

关节位置误差。按片段等权平均的世界关节 RMSE：

(6.1)\[\mathrm{RMSE}_{\text{pos}} =\frac{1}{|\mathcal{S}|}\sum_{s\in\mathcal{S}} \sqrt{\frac{1}{TJ}\sum_{t=1}^{T}\sum_{j=1}^{J} \big\|\hat{\mathbf{p}}_{s,t}^{j}-\mathbf{p}_{s,t}^{j}\big\|_2^{2}}\quad[\text{cm}],\]

其中 $\hat{\mathbf{p}}$ 由身体位姿与外部轨迹复合得到： $\hat{\mathbf{p}}_t^{j}=\mathbf{q}_t\odot\hat{\mathbf{b}}_t^{j}$。 因此这个指标同时依赖姿态质量与轨迹条件，换轨迹后不可直接比较（§7.5）。

身体朝向误差。只取水平分量，避免把翻滚分量算进来：

(6.2)\[\mathrm{RMSE}_{\text{yaw}} =\frac{1}{|\mathcal{S}|}\sum_{s}\sqrt{\frac{1}{T}\sum_{t=1}^{T} \mathrm{wrap}\!\big(\hat{\psi}_t-\psi_t\big)^{2}}\quad[^\circ],\]

$\mathrm{wrap}(\cdot)$ 把角差折回 $(-180^\circ,180^\circ]$。 注意世界朝向大部分由外部 $\mathbf{q}_t$ 决定，因此这个指标上升并不等于模型没学会转向。

接触期脚速。只在来源接触标签连续两帧成立时统计：

(6.3)\[v^{\text{foot}} =\frac{1}{|\mathcal{P}|}\sum_{(t,t+1)\in\mathcal{P}} \Big\|\mathbf{p}_{t+1}^{\text{foot}}-\mathbf{p}_t^{\text{foot}}\Big\|_2\cdot f_{\text{fps}} \quad[\text{m/s}],\]

$\mathcal{P}$ 是连续接触帧对集合，$f_{\text{fps}}=30$ Hz。这是式 (3.6) 左侧的离散实现， 标签本身是启发式的（§4.4），因此它只用于相对比较，且样本量小（5–24 帧对）。

接缝速度误差。衡量历史末帧到生成首帧的跳变：

(6.4)\[\varepsilon_{\text{seam}} =\Big\|\big(\hat{\mathbf{p}}_1-\mathbf{p}_0\big)-\big(\mathbf{p}_0-\mathbf{p}_{-1}\big)\Big\|_2 \quad[\text{cm/帧}],\]

右式第二项是历史段的末速。这一项下降说明衔接更平滑，但它不说明整体步态正确。

Token 交叉熵。即式 (3.4) 在验证集上的取值：

(6.5)\[\mathrm{CE}_{\text{token}} =\frac{1}{|\mathcal{V}|}\sum_{v\in\mathcal{V}}\Big(-\frac{1}{|\mathcal{M}_v|} \sum_{t\in\mathcal{M}_v}\log p_\theta\big(z_{v,t}\mid\cdot\big)\Big)\quad[\text{nats}],\]

$\mathcal{V}$ 为 48 条冻结验证片段，$|\mathcal{M}_v|$ 为该片段的监督 Token 数，合计 2,608。 这个量只反映"码分类得对不对"，不含解码误差——式 (3.1) 的 $D_\psi$ 完全不在这个指标里。式 (6.5) 与式 (6.1) 之间没有单调关系，§7.3 给出了具体反例。

加速比。处理吞吐用同一批样本的端到端耗时之比：

(6.6)\[S=\frac{T_{\text{base}}}{T_{\text{opt}}},\qquad T=\underbrace{\sum_{i}t^{\text{io}}_i}_{\text{文件打开/stat/目录}} +\underbrace{\sum_i t^{\text{cpu}}_i}_{\text{FK 与特征}} +\underbrace{\sum_i t^{\text{zip}}_i}_{\text{压缩}}.\]

profiling 显示 $t^{\text{io}}$ 占 19.87 s 中的 15.86 s，$t^{\text{zip}}$ 仅 0.32 s。 这就是为什么优化集中在 I/O 而不在压缩（§4.7）。

7.4  为什么 Run/Crouch 会退化：一个可检验的解释

数据审计给出了一条线索。记第 $i$ 条片段的 Actor 水平速度为 $v_t=\|\mathbf{q}_{t+1}[xz]-\mathbf{q}_t[xz]\|_2\cdot f_{\text{fps}}$， 统计其分位数 $Q_{0.1},\,Q_{0.5},\,Q_{0.9}$（米/秒，按帧汇总，排除补齐帧）：

  • Walk（48,443 帧差）：p10 / p50 / p90 = 1.291 / 1.650 / 2.000
  • Run（33,734 帧差）：1.247 / 3.750 / 5.000
  • Crouch（40,112 帧差）：1.453 / 1.650 / 2.250

而评估所用 CMC 轨迹的速度是 Walk 1.4、Run 4.0、Crouch 0.8 m/s。 定义分布偏移量为 CMC 速度在训练分布中的分位位置， 以 $Q_{0.1}$ 为下界则 Crouch 的偏移可写成

(7.1)\[\kappa=\frac{Q_{0.1}-v^{\text{cmc}}}{Q_{0.1}} =\frac{1.453-0.800}{1.453}\approx 0.449,\]

即 CMC 的蹲伏速度比训练分布的 $p_{10}$ 还低约 45%。相比之下 Walk 的 $\kappa=(1.291-1.4)/1.291\approx-0.084$（略低于 $p_{10}$ 之下但符号相反， 说明仍在分布边缘），Run 的 4.0 落在 $[1.247,\,5.000]$ 内、$\kappa\lt 0$。 也就是说：Walk 落在训练分布低端、Run 在分布内、Crouch 0.8 明显低于训练的 p10。 这解释了 Crouch 退化的一部分——模型没有见过这么慢的蹲伏位移， 而且它也没有显式的 Crouch 状态输入。 这是一条解释，不是一条已完成的因果证明：要证明它需要一次只改速度分布的受控实验，我们尚未做。

7.5  控制器条件探针：换一条轨迹会发生什么

敏感度用两个量刻画。第一个是 Actor 局部关节的 RMS 变化：

(7.2)\[\Delta_{\text{local}} =\sqrt{\frac{1}{TJ}\sum_{t,j}\big\|\hat{\mathbf{b}}^{\text{cmc},j}_t -\hat{\mathbf{b}}^{\text{teacher},j}_t\big\|_2^{2}}\quad[\text{cm}],\]

第二个是离散 Token 的不一致比例（而非欧氏距离，因为 Token 是类别量）：

(7.3)\[\rho=\frac{1}{L}\sum_{\ell=1}^{L} \mathbb{1}\big[z^{\text{cmc}}_\ell\neq z^{\text{teacher}}_\ell\big]\in[0,1].\]

若模型真的对轨迹敏感，换一条转向 90° 的轨迹应当显著改变 $\rho$。实测 Crouch 只有 $\rho=2.1\%$、$\Delta_{\text{local}}=0.50$ cm，这组小数字正是"模型没响应蹲伏状态"的量化证据。

7.6  上限诊断：解码器缺的是什么

为了区分「主干预测错了」与「解码器条件不足」，我们做了一个故意的 oracle 实验。 固定 Token（$z^{\text{cmc}}_\ell\equiv z^{\text{teacher}}_\ell$）后， 误差的分解为

(7.4)\[\underbrace{\mathrm{RMSE}(\hat{\mathbf{p}}(\mathbf{c}^{\text{ext}}=\mathbf{0}))}_{\text{零外部}} \;-\;\underbrace{\mathrm{RMSE}(\hat{\mathbf{p}}(\mathbf{c}^{\text{ext}}=\mathbf{c}^{\star}))}_{\text{oracle}} =\;\underbrace{\Delta_{\text{dec}}}_{\text{解码条件缺失}},\]

其中 $\mathbf{c}^{\star}$ 是来源未来的 pose-feature Root——推理期不可得。 因此式 (7.4) 右端是上界诊断的量，不是可部署收益。若 $\Delta_{\text{dec}}$ 很小， 说明瓶颈在主干；若很大，说明瓶颈在解码条件。实测 Walk 的 $\Delta_{\text{dec}}=6.03-4.86=1.17$ cm，Run 为 $0.93$ cm，Crouch 为 $1.77$ cm（§7.6 表 11）。

8  讨论、局限与缺陷清单

8.1  这份报告能支撑什么

  • Tokenizer 加 Pose Token 的两段式链路在本仓库跑通：数据、训练、检查点、离线推理、视频导出全链路可复现。
  • 固定验证口径下，20k 训练相对 2k 显著改善 Token 预测（−21.9%），且该改善在三个类别上方向一致。
  • 数据管线在保持逐数组等价的前提下把处理吞吐提到 1.69–1.80 倍，且有 24 次配对的哈希证据。
  • 时延在 Python 前向层面有约 6 倍余量（P95 21 ms 对 133 ms 预算）。

8.3  方法论上的经验

这次工作中最值得记录的不是某个指标，而是三处「差点把结论写错」的地方：

  1. 把 Actor 相对的骨盆特征当成 CMC Root。后果是把「模型跟随控制器」这一命题的验证污染了。 修复方式不是改解释，而是重建 sidecar 并逐字节复核。
  2. 把 down_t 当成可共享的超参数。它在源码里就是卷积层数， 层数不同则权重不可共享。方案里「一套码本服务双帧率」的结论因此被推翻。
  3. 把「接触候选」当成接触真值。启发式标签能用于相对比较， 但一旦用来宣称「脚滑已解决」就越界了。

共同点是：指标本身没错，错的是指标所依附的对象身份。 因此本报告把每个数字都附上它所属的条件（教师轨迹 / 控制器轨迹 / oracle）， 并在表 6 与表 13 中显式列出不可跨越的边界。

9  结论与下一步

MotionWeaver 已经建成一条可追溯的数据与训练链路：两套骨骼数据汇入同一目标骨架， 分词器与姿态主干可分离训练与替换，评测口径被冻结并可复现， 20,000 步训练在 Token 层面给出确定的改善。同时，世界姿态、接触质量与控制器响应三项指标 明确未达标，我们据此把当前检查点定位为可复现的基线，而不是可用产品。

下一步按依赖顺序排列：

  1. 补齐在线可得条件。把 Crouch / Gait / RotationMode 状态，以及 CMC 实际提供的 短时轨迹作为显式输入与掩码，替代当前「用来源未来 Root 当条件」的做法。
  2. 修正解码器条件。§7.6 表明 pose-root 条件是部分误差来源； 需要设计一个推理期可得的替代量（例如模型自预测的骨盆高度先验）， 并证明它不是变相的未来泄漏。
  3. 把 SOMA 数据真正接进训练。训练视图仍在构建；接入前必须先按来源家族 / 会话 / 镜像组划分， 再生成窗口，否则会产生跨分区泄漏。
  4. 完成 UE 闭环。NNE 导出、AnimGraph 重建、动画线程推理、蒙皮播放，以及 4 帧步长加播放延迟下的可操控体验，都需要在真实场景里验收。
  5. 用程序化模块兜住确定性约束。按表 5 的分工接入 Warping 与 Foot IK， 并实测回退阈值是否合理。

每一项目标都要同时报告 Token CE、世界姿态、接触脚速与 UE 实测四项， 不接受只报其中一项的「通过」。
