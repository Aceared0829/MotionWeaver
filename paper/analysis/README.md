# 姿态精度不蕴含接触保真度：全量 in-betweening 评测的二维切分

> **一句话结论。** 在整个 SOMA full-v1 测试集上（121,058 窗口 × 4 档参考 × 2 基线），
> 姿态误差与接触期脚速**总体强相关（r = 0.645–0.794，ρ = 0.856–0.927）**，
> 但在**同一难度分层内相关性骤降到 r = 0.147–0.279**。
> 也就是说，两者大部分共同变化来自「这个窗口难不难」这一混杂因素，
> 而不是「姿态一准，脚就不滑」的直接因果。
> 据此，仅以关节 RMSE 作为优化目标的动作生成，**没有理由预期脚滑会被解决**——
> 这与我们此前在 MotionWeaver 20k 上观察到的反例（Token CE 降 15%、世界 RMSE 反而 +4.6 cm）互相印证。

- 生成时间：2026-10-26
- 数据：`D:/MotionWeaverData/eval/full-v1-fps120/report.json`（585 MB，968,464 条逐窗口样本）
- 契约：`contracts/fps120`（`reference_guided_root_pose_v1`），test split 全部窗口
- 脚本：`paper/analysis/contact_pose_analysis.py`（一条命令复现全部数字与图）

## 1 这份分析在回答什么

动作生成文献几乎只用姿态误差（关节位置 RMSE / MPJPE / FID）衡量好坏。
但游戏与动画里真正被看见的失败是**脚在地上打滑**。两者是否同一件事，此前没有在
十万窗口这一粒度上被直接检验过。本分析用两个零成本基线（Hold / Lerp）作为探针，
把「姿态误差」与「接触脚速」放到同一张表上，并做了两次关键对照：

1. **难度对照**：补间收益是否只由窗口难度决定？
2. **分层对照**：控制难度后，姿态误差还能解释脚滑吗？

## 2 口径与边界（务必先读）

| 项 | 说明 |
| --- | --- |
| Root 轨迹 | **oracle**。`oracle_root_condition: true`，世界轨迹取真实动作。因此这是离线上界评测，不是在线生成能力。 |
| 接触标签 | **启发式**。`contact_foot_speed_mps` 只在来源接触标签连续两帧成立时统计；标签由脚速/高度阈值生成，不是传感器真值。适合相对比较，不适合绝对断言。 |
| 来源脚速 | 极低，中位 **0.016 m/s**。因此「倍数」会被放大；本文同时报绝对值。 |
| 加权 | 窗口等权（每窗口一次），与评测器 `per_clip_equal_weight` 一致。 |
| 样本筛除 | 只用 `contact_pairs ≥ 3` 的窗口参与接触统计，避免 1–2 帧对的噪声。 |
| 不含量化模型 | 本报告**不含任何训练模型**的结果，全部为零成本基线。 |

## 3 Q1：姿态误差与脚滑总体强相关

下表为 Lerp 基线在四档参考下的结果，n = 119,858 / 档。
「五分位比」= 姿态误差最高 20% 窗口的平均脚速 ÷ 最低 20% 的平均脚速。

| 参考档位 | Pearson r | Spearman ρ | 五分位最低 | 五分位最高 | 比值 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 无参考 | +0.645 | +0.856 | 0.036 m/s | 1.729 m/s | **47.7×** |
| 中间帧 | +0.718 | +0.889 | 0.029 | 1.593 | 55.3× |
| 终点帧 | +0.773 | +0.910 | 0.026 | 1.700 | 65.8× |
| 中间+终点 | +0.794 | +0.927 | 0.021 | 1.484 | **71.8×** |

两点值得注意：

- **秩相关远高于线性相关**（ρ 0.86–0.93 vs r 0.65–0.79）。关系是单调但非线性的：
  姿态误差从 0 增到 10 cm 时脚速涨得很快，再往上趋于饱和。
- **参考越多，相关性越强**。给的参考帧越准，姿态与接触就越「同步」，
  这在直觉上成立：参考帧把姿态钉住时，剩下的误差几乎全部转化为接触误差。

![姿态精度与接触保真度](out/figA-pose-vs-contact.png)

## 4 Q2：补间收益与窗口难度几乎无关

一个自然的解释是「难窗口改善多、易窗口改善少」。实测否定了它：

```
r(Hold RMSE, 相对改善) = +0.151    rho = +0.133    n = 121,058
```

| Hold RMSE 区间 (cm) | n | Lerp 相对改善 |
| --- | ---: | ---: |
| [0, 3) | 30,444 | −71.8% |
| [3, 6) | 12,280 | **−78.0%** |
| [6, 12) | 17,586 | −77.6% |
| [12, 25) | 26,091 | −74.8% |
| [25, 50) | 25,056 | −68.6% |
| [50, ∞) | 9,601 | −64.7% |

曲线是**倒 U 形**：最容易的窗口改善反而略小（−71.8%，因为本来就没多少可改），
最难的最差（−64.7%），中间段最好。也就是说**线插的收益存在一个与场景无关的稳定区间**，
而不是「越难越有用」。这个结论对评测设计有直接含义：只挑难样本做评测，会低估补间的平均收益。

四场景的系统性差异（A −68.5% / B −75.5% / C −73.3% / D −75.7%）主要来自**空间位移量**，
而非关节角度变化幅度——A 场景数秒内发生米级位移，线性插值在长距离上误差累积。

![难度与补间收益](out/figB-difficulty-vs-gain.png)

## 5 Q1b：控制难度后，相关性骤降——这是本报告最重要的一节

Q1 的高相关有一个必须排除的解释：**难度混杂**。难窗口的姿态误差大，难窗口的脚滑也大，
两者可以仅仅因此同向，而与「姿态是否准」无直接关系。
检验方法：把每个参考档内按 RMSE 分成十个十分位，**在每个十分位内部**重算相关。
若难度是唯一原因，层内 r 应接近 0。

| 参考档位 | 总体 r | 十分位内中位 r | 降幅 |
| --- | ---: | ---: | ---: |
| 无参考 | +0.645 | **+0.147** | −77% |
| 中间帧 | +0.718 | **+0.193** | −73% |
| 终点帧 | +0.773 | **+0.225** | −71% |
| 中间+终点 | +0.794 | **+0.279** | −65% |

**结论：总体相关中约三分之二到四分之三来自窗口难度这一混杂，不是姿态—接触的直接对应。**
层内仍留有 r ≈ 0.15–0.28 的残余正相关，说明两者并非完全无关；
但残余量级远不足以支撑「把 RMSE 压下去，脚滑就解决」这一推论。

![混杂检验](out/figD-confound.png)

图 D 还显示一个细节：**最低十分位（第一根柱）的层内相关显著高于其余（0.51–0.62）**。
在姿态已经很准的窗口里，误差与脚滑的耦合反而最紧——这与「精度一旦足够，
接触就成为主要矛盾」的直觉一致，但它只覆盖最准的那 10% 窗口。

## 6 Q3：脚滑的绝对量级

| 参考档位 | 倍数中位 | p25–p75 | 生成脚速中位 | 来源脚速中位 |
| --- | ---: | ---: | ---: | ---: |
| 无参考 | 18.5× | 8.1–35.9 | 0.309 m/s | 0.016 m/s |
| 中间帧 | 13.6× | 6.1–27.8 | 0.223 | 0.016 |
| 终点帧 | 12.5× | 5.2–27.7 | 0.199 | 0.016 |
| 中间+终点 | 8.9× | 3.9–20.6 | 0.138 | 0.016 |

即使是「上界」档（中间+终点双参考），脚速中位数仍是来源的 **8.9 倍**。
绝对值 0.138 m/s 对有经验的动画师而言是可察觉的滑步量级。

![脚滑倍数](out/figC-foot-slip.png)

按场景看，A 常规移动的生成脚速最高（0.30 m/s），D 开放交互最低（0.08 m/s），
与「位移越大、插值越差」一致。

## 7 这些结果支持什么、不支持什么

**支持：**

1. 在统一口径、十万窗口粒度上，姿态误差与接触保真度**不是同一件事**；
   以 RMSE 为唯一目标的优化，没有理由预期接触问题被解决。
2. 补间收益与窗口难度近似无关（r = 0.151），存在稳定的中间最优区间。
3. 零成本基线在接触维度上的表现极差（8.9–18.5 倍），
   这给任何学习式方法立了一道**容易打赢、但没人报过**的靶子。

**不支持：**

1. **不能**说「姿态精度与接触无关」——层内仍有 r ≈ 0.15–0.28 的残余正相关。
2. **不能**外推到在线生成。Root 是 oracle，接触标签是启发式。
3. **不能**当作训练模型的效果。本报告不含任何量化模型结果。
4. **不能**用倍数单独下结论。来源脚速仅 0.016 m/s，倍数天然被放大。

## 8 与 MotionWeaver 20k 那个反例的关系

技术报告 §8.3 记录了一个当时无法解释的现象：Run 片段上 Token CE 改善 15%，
但世界关节 RMSE 反而由 7.36 恶化到 12.00 cm。
本分析给出了一个可能的解释框架：**如果姿态误差与接触保真度在控制难度后只有弱耦合，**
**那么任何以 Token/姿态为目标的改进，都不保证在接触维度上同向。**
该反例是这一框架下的一个样本，但**它本身不是本分析的证据**——
两者口径不同（前者是单个训练检查点，后者是零成本基线）。

## 10 已知局限与下一步

| 局限 | 影响 | 下一步 |
| --- | --- | --- |
| 接触标签是启发式 | 绝对量级存疑，相对比较可用 | 引入人工标注子集做校准 |
| Root 是 oracle | 非在线能力 | 用录制 CMC 轨迹重跑同一分析 |
| 只有两个零成本基线 | 无法判断学习式方法的位置 | 在同一脚本里加入模型输出 |
| 未做显著性检验 | 大样本下几乎所有差异都显著 | 报效应量而非 p 值，或做 bootstrap 区间 |
| fps30 组未纳入 | 只覆盖 120 fps 主库 | 单独出 fps30 的对照 |

**下一步（按价值排序）**：

1. 把同一分析接到 MotionWeaver 20k 的输出上，检验「层内残余相关」在模型生成上是否同样成立；
2. 用录制 CMC 轨迹替换 oracle，看结论是否随轨迹来源改变；
3. 若（1）成立，则「接触条件化」有了明确的动机依据，可作为方法论文的核心论点。
