1　引言

1.1　问题背景

角色动画是游戏与实时三维应用中最消耗人力的资产之一。一段可用的角色动作需要经过动作捕捉或人工编排、曲线清理、脚部接触修正、与角色骨架匹配等多道工序，单段动作的制作周期常以天计。当一个项目需要数百至上千段动作时，制作成本与迭代速度会直接成为项目排期的瓶颈。

动作捕捉虽然缓解了人工编排的压力，却没有消除后续工序：捕获数据仍需按目标角色的骨架比例重新处理，仍需逐段检查是否存在滑步、穿模与姿态异常。这一环节目前高度依赖人工逐段观看与主观判断，缺少可批量执行、结论可追溯的验收手段。

1.2　现有做法的局限

（1）依赖人工关键帧与逐段修型。动作风格、节奏与细节需要动画师在曲线上逐帧调整，一旦角色骨架比例改变，先前的调整无法直接复用，需要重新制作。

（2）跨骨架复用需要重新处理。同一段动作数据在不同比例的骨架之间不能直接套用，重定向之后脚部接触、手部位置与身体朝向都需要重新校验，而校验本身又是人工密集的工作。

（3）训练结果缺少统一的评估口径。动作生成类模型常以训练损失作为进展指标，但损失下降并不等于姿态可用；缺少同配置、同数据划分的对照，容易把局部指标当作整体结论。

1.3　本软件的定位

本软件实现从动画数据采集、训练数据预处理与人工验收、离散姿态表示学习、条件姿态生成训练，到推理与可视化对照的完整流程，并提供中文图形操作界面与 Windows 启动入口。软件不依赖外部动画制作工具完成核心计算，动作数据的读取、校验、训练、导出与评估均在本地完成。

对应代码位置：README.md、docs/motionweaver-architecture.md、docs/repository-layout.md

5.2　动作数据表示

骨架。训练骨架由使用者按资产实际骨骼指定：身体根节点默认取骨盆，保留其下全部子骨骼；编辑器插件的唯一世界根轨道单独保存，不进入训练骨架，也不由模型生成。身体树之外的辅助骨骼（含虚拟骨骼）不参与训练。因此同一软件既可处理人形骨架，也可处理骨骼数量不同的其他骨架，特征维数随骨骼数变化而不是固定值。

特征分量。每根骨骼以局部平移与 6 维旋转表示。设身体骨骼数为 J，则全局表示每帧 12J+6 维，局部表示每帧 12J+5 维，双表示每帧 12J+10 维。分离身体的根轨迹与身体姿态，是为了让模型只负责它实际接收到的条件。

坐标与单位。导出数据使用引擎坐标系（厘米、Z 轴向上、四元数 xyzw），送入模型前统一转换为米、Y 轴向上，并消除每根骨骼的参考旋转，使其与正向运动学算法一致。回写引擎动画时需要恢复参考骨轴。

对应代码位置：data/runtime/unreal_dataset.py、model/MotionWeaver/representation/core/motion_reps/、model/MotionWeaver/geometry/quaternions.py

5.3　离散姿态表示学习

为什么把连续姿态变成离散编号。一段姿态在数值上是十几到几十个关节的位置与旋转，是连续量；连续量上的回归模型容易把细微误差摊到每一帧，表现为画面抖动。软件把连续姿态送入编码器压缩，再经量化器映射到有限个码字上，每帧姿态因此变成一组离散编号；解码器负责从编号还原姿态。这一步相当于给姿态建立一本有限的「词表」：相似的姿态落在同一个词上，不相似的姿态被分开。

两个直接好处。第一，生成模型的输出从「一串任意实数」变成「从有限词表里选词」，选择错误是可枚举、可统计的，训练目标因此可以直接用词表上的交叉熵衡量，而不是只看像素级的重建误差。第二，码本与骨架、归一化统计量绑定，检查点加载时会核对骨架与统计量，换骨架或换统计数据不会被误用。

多码本与条件解码。量化器按多个头并行量化，同一帧姿态由若干码字共同表示；解码器接收码字的同时还接收条件信息，因此在还原姿态时可以考虑上下文，而不是逐帧独立解码。

5.4　条件生成模型

生成阶段的条件有两类：一类是历史姿态，只取最近若干帧的真实姿态，不输入未来真实姿态；另一类是身体在世界中的运动轨迹（位置与朝向随时间的变化）。前者决定「刚才是什么样子」，后者决定「接下来往哪走」。

模型先用历史姿态编码，再把轨迹换算成以首帧身体为原点的局部坐标，与编码结果一起作为条件，输出后续若干帧的姿态编号，最后交由解码器还原为身体姿态。因此模型输出的是相对身体的表现姿态，世界位移仍由外部运动组件决定，两者职责不重叠。

训练时同一数据契约还提供一种轻量直接回归模型作为对照，它不经过离散码本、按骨骼直接回归位置与 6 维旋转。两者共用数据划分与评估脚本，但报告分开署名，避免把对照模型的成绩计入本模型。

对应代码位置：inference/runtime/motionweaver.py（predict_with_actor_root）、training/models/backbone/motionweaver_pose_model.py、model/MotionWeaver/backbone/neural_modules/pose_backbone.py；对照模型 training/pretrain/train_conditioned_pose.py

5.5　骨架适配与导出

骨架适配。模型在训练骨架的空间里生成姿态，使用者的目标骨架若比例不同，需要先做重定向：按骨骼语义映射（骨盆、左右髋、脚踝、脚掌、双手等）建立对应关系，再做旋转基变换与骨长处理。软件的重定向入口区分单段与批量两种用法，批量模式逐段记录失败原因，不因个别片段失败中断整个批次。

导出。训练得到的检查点包含优化器状态，体积与用途都不适合直接部署。导出入口把检查点转换为不带优化器的 FP32 推理包，包内带可迁移的骨架定义、归一化统计量与配置，并通过随包提供的加载函数在原地重新定位资源。导出过程逐值校验权重，不做 FP16/INT8 转换或剪枝，因此推理结果与训练时的数值一致。若运行环境已能自行提供兼容的码字，可只导出码本与解码器，去掉编码器以减小体积。

5.6　训练质量与评估口径

真实帧掩码。动作片段长短不一，短片段需要补齐才能组成批。补齐帧只在卷积上下文中存在，不参与重建损失与运动损失，避免模型把补齐产生的静止画面当成真实动作学下来。

几何约束。在重建项之外增加若干几何项：骨盆对齐后的关节点位置误差、根轨迹误差、脚部端点误差、速度与参考接触约束。各几何项权重可单独设置，设为 0 即得到消融对照。

采样策略。按真实长度分桶，短桶只补齐到批内最短长度的有限倍数；对困难类别在原有权重上加权。该策略只改变取样顺序与补齐长度，不改变网络参数、原生帧率、数据划分与训练步数。

评估口径。评估恢复源的初始朝向与平移，与服务端在同一采样时刻对照，分别报告世界位置、骨盆对齐姿态、根水平与高度误差。所有对照必须同配置、同步数、同数据划分，禁止把局部样本的指标当作整体结论。接触类指标必须同时给出参与统计的接触帧对数量，帧对不足时不报告该指标。

6.4　模型训练

功能概述。统一训练入口，支持三类模型：离散姿态表示模型（编码器、多码本量化器与条件解码器）、条件姿态生成模型（Pose Token 主干）、以及旧版的根轨迹模型。前两类构成本软件的主线，第三类保留用于兼容既有数据契约。训练过程保存配置、逐行指标、周期检查点与最终权重，支持中断后从检查点恢复。

操作步骤。①先训练离散姿态表示模型，得到码本检查点；②再以该检查点作为前提训练条件姿态生成模型；③训练中通过指标文件观察损失变化，需要中断时按 Ctrl+C，检查点目录保留最近一次的周期检查点；④需要续训时加恢复参数并给新的总步数。

# 第一步：训练离散姿态表示模型
.venv/Scripts/python.exe training/pretrain/train_unreal.py \
  --model vqvae --dataset data/prepared/native30 \
  --output training/runs/native30 --native_quality \
  --max_steps 20000 --batch_size 4 --accelerator gpu

# 第二步：训练条件姿态生成模型，必须给出上一步的码本检查点
.venv/Scripts/python.exe training/pretrain/train_unreal.py \
  --model pose --dataset data/prepared/native30 \
  --output training/runs/native30_pose \
  --vqvae training/runs/native30/checkpoints/final.ckpt \
  --max_steps 20000 --accelerator gpu

# 续训：--max_steps 是恢复后的总步数
.venv/Scripts/python.exe training/pretrain/train_unreal.py \
  --model vqvae --dataset data/prepared/native30 \
  --output training/runs/native30 --resume training/runs/native30/checkpoints/last.ckpt \
  --max_steps 30000

6.6　姿态生成推理

功能概述。加载正式姿态权重与码本，按给定轨迹条件与最近若干帧历史姿态，生成后续若干帧的身体姿态。推理入口提供两条路径：以外部给定的身体轨迹为条件、输出相对身体的表现姿态；以及仅用于离线诊断的、以姿态特征内的根分量为输入的模式。两条路径的编码方式不同，不可混用输入。

使用限制。模型只输出相对身体的表现姿态，世界位移由外部运动组件决定，模型不生成世界轨迹；在线输入只使用最近 4 帧历史姿态，不输入未来真实姿态；轨迹条件以首帧身体为原点换算为局部坐标，若外部数据未按时对齐会被拒绝；与三维引擎的实时闭环与蒙皮接线尚未完成，当前结果用于离线验证与对照，不构成引擎内运行时。

7　总结

本软件实现了一条从动画资产到可观看生成结果的完整链路：其一，编辑器插件把工程内的动画序列批量导出为分离了世界根轨道与根局部身体姿态的批次数据，并记录有理数帧率与逐帧时间戳；其二，预处理入口把批次校验、转换、切片为带契约描述的训练数据集；其三，本地验收服务让使用者逐帧对照原始骨架与重定向后骨架，把结论写成可追溯的记录；其四，训练入口支持离散姿态表示模型与条件姿态生成模型，并提供真实帧掩码、几何约束与困难类别采样等质量控制选项；其五，导出与推理入口把检查点转成可迁移的推理包，按外部轨迹条件生成后续姿态；其六，可视化与评测入口把结果渲染为可观看画面与同条件对照报告。

与常见的「只报告训练损失」的做法相比，本软件有两点不同。第一，质量判定以同配置、同步数、同数据划分的对照为准，评估在恢复源初始朝向与平移后按同一采样时刻比较，接触类指标必须同时给出参与统计的帧对数量，帧对不足时不报告，避免把局部样本当作整体结论。第二，模型输出被限定为相对身体的表现姿态，世界位移交由外部运动组件决定，两者职责不重叠，因此生成结果可以与不同的运动来源在相同接口下对照，而不必为每个来源重做一套评估。

当前版本仍存在局限。姿态生成部分虽有完整的训练与推理链路，但世界姿态误差与脚部接触质量尚未达到可用门槛，其中蹲伏响应依赖状态输入而模型尚未接入该输入；离散表示的容量与几何细节之间存在折衷，短姿态改善会伴随部分常规动作退步。工程侧，与三维引擎的实时推理闭环、骨骼动画输出插件、运动组件接线与多人并发均未完成，因此本软件目前定位于训练、评估与实验对照，不构成引擎内的正式运行时。
