# 软著撰写提示词（提示词库）

> 用法：把对应的提示词整段复制给 AI，附上它需要的输入文件。
> 一次只跑一个提示词，跑完人工过一遍再跑下一个。**不要一次性让 AI 写完整本手册。**

---

## P0 · 总控提示词（每次对话开头都贴这一段）

```
你是软著材料撰写助手。本次任务是为「MotionWeaver 角色动画生成系统 V1.0」撰写软件著作权登记材料。

硬性约束（违反任何一条都算失败）：
1. 只写仓库里真实存在的功能和代码，不得虚构模块、参数、指标、界面。
2. 无法从代码/文档确认的内容，写「（待确认）」并列出需要什么文件才能确认，不要猜。
3. 中文技术文档语体，陈述句，不用"我们"，不用营销词（颠覆、领先、革命性）。
4. 不出现任何第三方商标名（NVIDIA、Unreal Engine、MuJoCo、GR00T、MotionBricks 等）在正文里作为我方功能描述；上游来源只在"来源说明"一节提及。
5. 每个功能点必须能对应到具体文件路径或命令，写在括号里作为内部核对注释（这些注释在导出 Word 前会被删掉）。
6. 输出 Markdown，不要输出 HTML（HTML 由后续步骤统一生成）。

输出前自检：逐条列出本次内容里所有数字和专有名词，标注每个的来源文件。
```

## P1 · 系统能力清单（先把地基打准，最先跑）

```
inference/cli/、inference/export/、training/pretrain/、data/runtime/ 下的文件名清单。

任务：产出一份「系统能力清单」，作为后续所有文档的唯一事实来源。

表格列：
| 编号 | 能力名称 | 一句话说明 | 对应入口（文件/命令） | 输入 | 输出 | 是否已完成 |

要求：
- 只收录有实际代码入口的能力，纯文档设想的不收。
- 「是否已完成」只填三档：已完成 / 部分完成 / 实验性，并给一句依据。
- 按数据 → 训练 → 导出 → 推理 → 界面 的顺序排。
- 最后单列一节「明确不具备的能力」，把 README 里写"后续工作/开发目标"的都列进去。
```

## P2 · 说明书正文（分节生成，一次只跑一节）

### P2.1 引言 + 软件编写目标 + 适用领域

```
基于 P1 的能力清单，撰写说明书的前三节，合计 1200-1600 字。

结构：
## 1 引言
- 第1段：问题背景。角色动画制作中，动画资产制作周期长、成本高；从已有动作数据学习并生成新姿态是当前的研究与工程方向。不要写"随着人工智能的快速发展"这类套话。
- 第2段：现有做法的局限。明确写两点：（a）依赖大量人工关键帧；（b）跨骨架复用需要重新制作。要具体，不要泛泛而谈。
- 第3段：本软件做了什么。一句话说明：本软件实现从动画数据采样、姿态表示学习、到目标骨架姿态生成的完整流程，并提供可视化操作界面。

## 2 软件编写目标
说明本软件要解决的三个具体问题（对应 P1 清单），每条一句话。不要承诺没做的功能。

## 3 适用领域
写 2-3 个适用场景，每个场景说明"谁用、用来干什么、解决他什么问题"。
不要写"适用于所有需要动画的场景"这种废话。

风格要求：中文技术文档，不用第一人称，不堆术语，每段不超过 5 行。
```

### P2.2 运行环境

```
根据仓库的 pyproject.toml、setup.py、training/requirements.txt、inference/requirements-demo.txt、
README.md 的"快速开始"部分，撰写「运行环境」一节。

需覆盖：
1. 硬件环境：CPU、内存、磁盘、GPU（如需要）。有明确版本/容量要求的写清楚，没有的写"推荐"。
2. 软件环境：操作系统、Python 版本（注意仓库里有 3.12 和 3.10 两条路线，分别说明用途）、
   关键依赖库及版本（只列 requirements 里真实出现的，不要编版本号）。
3. 目录结构要求：数据、权重、输出分别放在哪里。

格式：用表格 + 简短说明文字。总计 400-600 字。
凡是从 requirements 里读到的版本，写在括号里标注来源文件名。
```

### P2.3 系统设计思路（技术核心，最重要的一节）

```
根据 P1 能力清单 + docs/motionweaver-architecture.md，撰写「系统设计思路」一节，1500-2000 字。

要求按"数据流"讲，而不是按代码目录讲：
1. 数据采集与表示：动画数据如何被采样、骨架如何定义、姿态特征包含哪些分量。
2. 姿态表示学习：离散化表示的原理（用大白话解释为什么要把连续姿态变成离散码），
   以及这样做的两个好处。
3. 生成模型：给定条件（历史姿态 / 未来轨迹）如何生成后续姿态。
4. 骨架适配：如何把生成结果映射到目标骨架。
5. 导出与运行时：模型如何被导出、如何被外部程序调用。

每一部分配一句"对应代码位置：（路径）"。
不要抄论文摘要，要用工程视角讲清楚"数据从哪来、经过什么、变成什么"。

最后画一个 ASCII 数据流图，宽度不超过 80 字符。
```

### P2.4 软件功能说明（按模块，这是手册主体，至少 8 页）

```
为每个功能模块单独写一小节，格式固定：

### X.Y 模块名称

**功能概述**：（2-3 句）
**操作步骤**：
① ... ② ... ③ ...
**界面说明**：（若无独立界面，写"命令行方式，示例命令如下"并给一条真实命令）
**输入 / 输出**：（明确格式）
**使用限制**：（必须写，写真实存在的限制）

模块清单（按 P1 定稿）：
- 数据采集与导出模块
- 数据预处理模块
- 模型训练模块
- 模型导出模块
- 姿态生成推理模块
- 可视化交互界面模块

每个模块 250-400 字。命令必须能从 README 或 argparse 里找到依据，找不到就写（待确认）。
```

### P2.5 总结

```
写 300-400 字的总结。结构：本软件做了什么（3-4 项）→ 与同类方案相比的特点（2 项，要具体）→ 当前的局限（1-2 项，诚实写）。
不要出现"填补空白""国际领先"这类词。
```

## P3 · 源代码文档（3000 行 / 60 页）

### P3.1 选取哪些代码

```
任务：从仓库中挑选 3000 行源代码用于软著提交，要求能体现软件核心功能。

规则：
1. 优先选与说明书功能说明章节直接对应的代码（版权中心希望代码和文档对得上）。
2. 排除：测试文件、第三方源码、自动生成的代码、空行与纯注释块（注释要保留在行内）。
3. 选 8-12 个文件，单个文件不超过 400 行；如文件过长，选其中核心函数段。
4. 首尾各占一半：前 1500 行取"数据与模型定义"，后 1500 行取"训练与推理入口"。

输出一张表：
| 顺序 | 文件路径 | 行号范围 | 行数 | 在说明书中的对应章节 |

最后核对总行数是否在 2950-3050 之间（每页 50 行 × 60 页）。
```

### P3.2 提取与排版

```
按 P3.1 的清单，从仓库提取代码，输出成单页 50 行、每页带页眉的格式：
页眉格式：MotionWeaver 角色动画生成系统 V1.0    第 N 页 / 共 60 页

要求：
- 保留原有缩进和注释，不要重新格式化。
- 不要横向溢出（单行不超过 100 字符，超长的行按 Python 续行规则手动折行，不给代码加省略号）。
- 每页严格 50 行（最后一页不足 50 行则补空行）。
- 输出为 HTML（<pre> + 分页 div），由后续步骤转成 PDF/Word。
```

## P5 · 一致性检查（最后跑，很重要）

```
任务：对已完成的说明书全文做一致性检查，输出问题清单。

检查项：
1. 术语一致性：同一概念是否用了多个叫法（如"检查点"vs"权重文件"）。
2. 功能与代码一致性：说明书中每个功能，是否都能在 P3 选出的源代码里找到对应实现。
3. 数字一致性：所有数字（行数、页数、版本号、参数值）是否前后一致。
4. 虚构检测：逐条列出所有"可能是 AI 编的"表述（含具体数字但无来源、含功能名但代码里找不到）。
5. 禁用词扫描：列出文中的营销词、绝对化表述。

输出：表格（问题 | 位置 | 建议改法），严重问题排前面。
< 10 个问题就不要停下来问，直接改。
```

## 附：绝对不要写的几类句子

| 类型 | 例子 | 为什么 |
|---|---|---|
| 套话开场 | "随着人工智能技术的飞速发展……" | 查重和评审都反感 |
| 空泛承诺 | "可广泛应用于各类游戏与影视场景" | 无法核实，反而降低可信度 |
| 虚构指标 | "生成速度提升 300%" | 没有实测依据，是骗审 |
| 商标滥用 | "基于 Unreal Engine 的……" | 正文不写第三方商标 |
| 自我拔高 | "填补国内空白""国际领先" | 软著是登记不是评奖 |
