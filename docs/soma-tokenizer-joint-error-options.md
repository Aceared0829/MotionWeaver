# 关节还原误差：问题诊断与四个候选方案

> 审查稿。本文只做分析与对比，**未改动任何训练代码**。
> 所有数字来自本机实测（权重 `D:\MotionWeaverData\training_runs\entropy_20k\checkpoints\final.ckpt`，8 段 B/C 场景 64 帧窗口）。

---

## 一、先说结论（一页读完）

### 问题是什么

模型训练损失停在 0.36 左右、重建指标看着不错，但把重建结果还原成关节位置后，**平均关节误差 1.72 米、位置 RMSE 1.04 米**。两者不矛盾，因为训练损失衡量的是 941 维归一化特征的平均差异，而骨骼动作用米衡量。

### 根因是两件独立的事

| 编号 | 误差来源 | 实测大小 | 为什么现有损失管不到 |
|---|---|---|---|
| **E1** | 根轨迹（水平速度预测错误，积分后漂移） | 末帧约 **1.9 米** | 根只有 4/941 维；积分漂移不体现在单帧特征差里 |
| **E2** | 相对关节位置 `ric_data`（隔一个标准差） | 约 **0.69 米** | 231 维混在 941 维里被平均稀释 |

只修其中一个，另一个仍然是米级误差（实测：只换真值根 → 剩 1.46 米；只换真值关节位置 → 剩 1.16 米）。

### 四个方案，一句话版本

| 方案 | 一句话 | 改网络？ | 重训？ | 推荐度 |
|---|---|---|---|---|
| **A 关节位置损失** | 还原成米制关节，直接罚米 | 否 | 是 | ★★★★★ |
| **B 根积分 + ric 原尺度** | 只罚漂移的根轨迹和未归一化的关节位置 | 否 | 是 | ★★★★☆ |
| **C 加大根和 ric 权重** | 仍在归一化空间，只调系数 | 否 | 是 | ★★☆☆☆ |
| **D 改表示** | 根直接预测位置，不再积分速度 | 是 | 是 | ★☆☆☆☆（现阶段） |

**建议先做 A**。它不是最省事的，但只有它同时对齐"训练目标"和"验收指标"。

## 二、诊断证据（为什么确定是 E1 + E2）

### 2.1 先排除评测本身有问题

| 检查 | 结果 | 结论 |
|---|---|---|
| `global → local → global` 恒等反变换 | 关节 MAE **4.3e-8 米** | 坐标链闭合，不是评测换算错 |
| 原始往返（`inverse` 还原输入） | **1.6e-7 米** | 官方自校验门槛 0.03 米，通过 |
| local 与 global 两条还原路径对比 | 差异 **1.4e-7 米** | 两条路径等价，任选其一都可信 |

### 2.2 误差不是被单条坏样本拉高的

| 片段 | 误差 |
|---|---|
| 中位数 | **1.07 米** |
| 范围（除最差） | 0.44 – 1.52 米 |
| 最差单条（frog_jump） | 6.31 米 |

### 2.3 分组替换实验（把真值填回某一组，看误差剩多少）

| 填回真值的组 | 位置 MAE | 根误差 | 非根误差 | 解读 |
|---|---|---|---|---|
| 不填（原始重建） | **1.717 米** | 1.156 | 1.724 | 基线 |
| 只填**根** | 1.457 米 | ~0 | 1.475 | **E2 仍在** |
| 只填 **`ric_data`** | 1.156 米 | 1.156 | 1.156 | **E1 仍在** |
| 填 `global_rot_data` | 1.717 米 | 1.156 | 1.724 | 完全不变 |
| 填 `local_vel` | 1.717 米 | 1.156 | 1.724 | 完全不变 |
| 填 `foot_contacts` | 1.717 米 | 1.156 | 1.724 | 完全不变 |

**关键发现**：朝向（`global_rot_data`）、速度、脚接触换成真值后，位置误差**一点没变**。因为当前评测用 `joint_positions_from="ric_data"`，关节位置只由"根轨迹 + `ric_data`"决定。所以朝向重建得好不好，这个指标看不出来 —— 这本身是评测口径的一个局限，后文会讨论。

### 2.4 根轨迹是怎么漂的

| 帧 | 0 | 8 | 16 | ... | 64 |
|---|---|---|---|---|---|
| 根位置误差 | 0 | 3.6 厘米 | 大幅上升 | → | **约 1.9 米** |

第 0 帧为 0、单调累积 → 这是**速度积分**的特征，不是位置偏移。

| 量 | 真值 | 预测 |
|---|---|---|
| 水平速度（X, Z） | (-0.28, **2.55**) m/s | (0.11, **-0.81**) m/s |

方向和大小都错。64 帧 = 0.53 秒，这个速度差积出来正好是米级。

### 2.5 一个必须说清楚的坑：根高度恒为 0

`local` 表示的第 4 个根通道（`global_root_y`）统计 **std = 0.0**，真值和预测都是 0。即这批数据里根高度这一维**完全没有信息**。

这意味着：**不要**把"根高度学不会"当成误差来源。文中所有 Y 方向误差都来自 `ric_data`（把 `ric_data` 换成真值后 Y 误差变成 0），与根高度无关。

### 2.6 为什么 loss 0.36 可以和 1.7 米共存

| 量 | 数值 |
|---|---|
| 训练损失 | 941 维归一化特征的 **平均** SmoothL1 ≈ 0.36 |
| `ric_data` 归一化误差 | ≈ 1.05 → 乘自己的 std → **约 0.69 米** |
| 根速度归一化误差 | 0.21 → 乘 std（10–17）→ 两个速度通道分别约 **3.4 / 4.5 m/s** |
| 根在总额失中的权重 | **4/941 ≈ 0.4%** |

SmoothL1 在误差 > 1 之后变成线性，梯度不再随误差增大；941 维再平均一次，单组的米级误差就被摊平了。**继续加训练步数不会把 1 米变成厘米**，必须改损失。

## 三、四个方案详解

### 方案 A：还原到关节位置后直接罚米制误差

**核心思路**：既然验收指标是"米制关节误差"，就让训练损失也看这个量。

**实现位置**：`training/models/vqvae/motion_vqvae.py` 的 `loss()` 中，复用训练里已经算过的 `pred_joints_output`（现有代码为算脚滑已经调用了 `inverse`，见 L265–277），取出 `posed_joints`，与真值关节位置算 SmoothL1 或 MSE。

**可行性已实测**：

| 检查 | 结果 |
|---|---|
| 关节位置对 `recon` 可导 | ✅ `requires_grad=True` |
| 梯度是否有限 | ✅ 有限，非零元素占 **24.87%** |
| `inverse` 前向（64 帧，预热后中位） | **4.25 ms** |
| 反向（预热后中位） | **5.32 ms** |
| bs=4 每步额外开销估算 | 约 **20–40 ms** |

**注意**：这个方案有一个天然的便宜路径——现有代码**已经**在算 `inverse` 拿脚滑（`l_skate_contact`），只是没把关节位置拿去算损失。所以增量成本可能远低于独立实现。

**但这里有一个必须先解决的技术障碍（实测发现）**：

现有 `l_skate_contact` 与 `l_joint_vel` 调用 `inverse` 时**没有传 `init_heading_info`**（`motion_vqvae.py` L265–277 与 L306–312）。而推导出的根朝向依赖这个信息。诊断脚本里对比过：不传 `init_heading_info` 时，根位置的朝向还原不了，关节位置会出现**刚体旋转式的整体偏移**（历史上曾观测到 Kabsch 对齐能把 143.94 cm 降到 19.66 cm，旋转矩阵接近绕 Z 轴 180°）。

因此方案 A 落地时必须：

| 要做的事 | 原因 |
|---|---|
| 训练时也传 `init_heading_info` | 否则用来算损失的"关节位置"本身就带固定旋转偏差，罚了也罚错 |
| 或者改用"局部坐标下的关节位置"做损失 | 绕开朝向依赖，但需额外定义 |

**这一条如果不处理，方案 A 会训练出一个"朝向被人为旋转 180° 仍判为正确"的模型。** 这是本方案最大的隐藏风险，必须在动手前确认。

**优点**
- 训练目标和验收指标完全对齐，不存在"指标好看但误差大"的缝隙
- 同时覆盖 E1 和 E2（因为它看的是最终位置）
- 不改网络结构，不改表示，checkpoint 兼容

**缺点**
- 米制误差量纲大（厘米到米级），**必须仔细调系数**，否则会压垮重建损失
- 需要 `SmoothL1` 或 Huber，直接 MSE 容易被离群帧主导
- 每步多一次反向

**风险与缓解**

| 风险 | 缓解 |
|---|---|
| 系数过大导致重建崩坏 | 从 0.01 起，看 `l_recons_pose` 是否稳定 |
| 离群帧（如 frog_jump 6.3 米）主导梯度 | 用 SmoothL1/Huber 而非 MSE |
| 与 `joint_vel_loss` 重复惩罚 | `joint_vel_loss_coeff` 目前是 2.0，可能需要下调 |

### 方案 B：根积分 + `ric_data` 原尺度

**核心思路**：不还原到关节，只针对两个已确认的病灶分别加损失。

**两部分**
1. **根轨迹损失**：对归一化的根通道反归一化 → `compute_root_pos_and_rot` → 得到 `cumsum` 后的根位置 → 与真值根位置算误差。
2. **`ric_data` 原尺度损失**：把 `ric_data` 反归一化回米，再算误差，避免被归一化尺度和 941 维平均稀释。

**可行性已实测**：

| 检查 | 结果 |
|---|---|
| 根轨迹可导 | ✅ `requires_grad=True` |
| 梯度有限 | ✅ 有限 |
| 梯度非零元素占 **0.21%** | ✅ 正好只命中根通道，不污染其他维度 |
| 根前向（64 帧，中位） | **2.70 ms** |
| 根反向（中位） | **1.06 ms** |

**优点**
- 比 A 轻（反向 1 ms vs 5.3 ms）
- 精准打击已确认的两个病灶，可解释性强
- 不改网络，checkpoint 兼容

**缺点**
- **不覆盖 E2 之外的身体误差**：如果身体误差不只是 `ric_data` 的尺度问题，而是更高阶的形态错误，这个方案看不到
- 仍然没对齐最终验收指标（它是 proxy）
- 两个新系数要调

**风险与缓解**

| 风险 | 缓解 |
|---|---|
| 只修根不修身体，指标看着好但关节仍错 | 同时做 A，或至少在评测里拆开报告根/非根 |
| 根位置损失在长窗口主导梯度 | 按帧归一（除以窗口长度） |

---

### 方案 C：加大根和 `ric_data` 的权重（最小改动）

**核心思路**：不动结构，只调现有系数。

**现状**（`motionweaver_vqvae.yaml`）：

| 系数 | 当前值 |
|---|---|
| `global_root_loss_coeff` | 0.5 |
| `local_root_loss_coeff` | 0.5 |
| `commit_loss_coeff` | 0.02 |
| `skate_contact_loss_coeff` | 0.01 |
| `joint_vel_loss_coeff` | 2.0 |

**为什么它治不了根因**：这些系数作用的仍然是**归一化后的单帧特征**。根速度预测错 3–4 m/s 时，它的归一化误差只有 0.21，**再乘 10 倍系数，梯度信号依旧建立在"单帧特征差"上，而不是"积分后的位置差"**。积分误差靠加权是补不回来的。

**优点**：改一行、零代码、零风险探测成本。
**缺点**：机制上不解决 E1；对 E2 有部分作用（相当于给 `ric_data` 加权），但依然是归一化空间。

**结论**：只作为**对照实验**保留，不作为主方案。

---

### 方案 D：改表示，根直接预测位置

**核心思路**：把根表示从"旋转速度 + 线速度（需积分）"改成"直接给位置"，从机制上消除积分漂移。

**为什么现在不考虑**：

| 障碍 | 说明 |
|---|---|
| 需要改 `DualRootGlobalJoints` 表示层 | 影响数据统计量、checkpoint、ONNX 导出、UE 端 |
| 全部已有权重失效 | `tok_BC120`、`entropy_20k` 等都不能再加载 |
| 与上游官方表示分叉 | 官方 `GlobalRootGlobalJoints` 就是速度表示，改了就难以对比 |
| 上游推理侧要同步改 | UE 集成假设了当前表示 |

**优点**（如果做）：从根上消除漂移，理论上最干净。
**缺点**：改动面覆盖数据、训练、导出、引擎四层，现阶段成本远超收益。

## 六、必须保留的局限

1. **8 段样本量小**，且全部来自 B/C 场景。结论不能外推到 A/D 场景。
2. **当前指标看不到朝向**。`joint_positions_from="ric_data"` 只由根 + `ric_data` 决定，朝向、速度、脚接触的错误在这个数字里完全不体现。真实部署时朝向错误会有明显视觉影响。
3. **根高度这一维在本数据上恒为 0**，是无信息维度。不要据此得出"高度学得好"的结论。
4. **训练损失与评测指标本就不是一回事**，本文只是指出两者差距过大、需要对齐，并非说现有损失写错了。
5. 本文所有"预期效果"均为推断，未经训练验证。
