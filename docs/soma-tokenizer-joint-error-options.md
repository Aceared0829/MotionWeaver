## 零、方案 A 的最终结论

**一句话：关节位置损失让 `joint_rmse` 变化 +0.10 cm（+0.12%），小于种子噪声 0.56 cm，符号检验 p=0.75。判定：无可靠效应，不推荐启用。**

但在跑出这条结论之前，必须先记录一个**比方案 A 重要得多**的发现：之前所有实验都建立在一个错误的归一化口径上。

### 0.1 致命缺陷：训练与评测喂了不同的分布（已修复）

| 项 | 内容 |
|---|---|
| 症状 | 全库训练 20k 后 `joint_rmse` 从 108 cm 暴涨到 310–366 cm，而训练损失仍在下降 |
| 根因 | `motion_vqvae.training_step` 用 `change_first_heading(..., is_normalized=True)`，但 `SomaRealtimeCollate` 产出的是 `to_normalize=False` 的**原始**特征；评测 `evaluate_recon.run_one` 用 `is_normalized=False`，是正确的一次归一化 |
| 后果 | 训练喂给 `pose_net` 的 body 与评测不是同一分布；20k 前模型只输出近似常量，两条路径「一致地差」，掩盖了问题 |

实测（16 clip × 72 帧，local body）：

| 转换链 | body std | 与「理论上正确的写法」的 max\|d\| |
|---|---|---|
| 训练声明 `is_normalized=True`（旧） | 0.9669 | **862.40** |
| 评测 `evaluate_recon` 的写法 | 0.5845 | **6.85e-6**（≈0，评测是对的） |
| 理论正确：`glob.normalize` 后 `is_normalized=True` | 0.5845 | 0 |

**修复方式**：新增显式开关 `inputs_are_normalized`，两条数据入口相反，必须按来源声明：

| 数据入口 | 落盘/产出时的归一化状态 | 取值 |
|---|---|---|
| `--dataset`（`build_unreal_training_set`） | 落盘前已做 `(x-mean)/std` | `true` |
| `--soma_views`（`SomaRealtimeCollate`） | `to_normalize=False`，原始特征 | `false` |

`train_unreal.py` 自动设置：`conf.model.args.inputs_are_normalized = not bool(getattr(args, "soma_views", None))`。

**测试**：`tests/test_training_input_normalization.py`（6 项），变异检查 **4/4 全抓**；全量 **171 passed**。

### 0.8 更根本的问题：码本塌缩（未解决）

修复归一化后冒出一个更严重的问题——`perplexity_pose` 在 20k 步后就塌到 **1.000**：

| bucket | recons | perplexity |
|---|---|---|
| 0–10k | 0.2611 | 1.876 |
| 10k–20k | 0.2592 | 1.190 |
| 20k–30k | 0.2613 | **1.000** |
| 30k–40k | 0.2593 | **1.000** |
| 40k–50k | 0.2576 | **1.000** |

perplexity=1.0 意味着**每批所有 token 用同一个码字**，tokenizer 实际退化成自编码器。
`nb_code=32^8`（per_head=32）几乎全闲置。

这解释了方案 A 无效的机理：**码本里没有可被优化的信息**，在 941 维特征的均值损失上下压 0.1 cm 是做不到的。

```
关节 RMSE 85cm 这一档，瓶颈不在损失函数，而在：
  1. 码本只用 1/32 的容量（perplexity 1.0）
  2. 141 帧的压缩比下，误差是结构性的
```

## 一、以下为原始分析（方案对比依据）

> 所有数字来自本机实测（权重 `D:\MotionWeaverData\training_runs\entropy_20k\checkpoints\final.ckpt`，8 段 B/C 场景 64 帧窗口）。


### 问题是什么

模型训练损失停在 0.36 左右、重建指标看着不错，但把重建结果还原成关节位置后，**平均关节误差 1.72 米、位置 RMSE 1.04 米**。两者不矛盾，因为训练损失衡量的是 941 维归一化特征的平均差异，而骨骼动作用米衡量。

### 根因是两件独立的事

| 编号 | 误差来源 | 实测大小 | 为什么现有损失管不到 |
|---|---|---|---|
| **E1** | 根轨迹（水平速度预测错误，积分后漂移） | 末帧约 **1.9 米** | 根只有 4/941 维；积分漂移不体现在单帧特征差里 |
| **E2** | 相对关节位置 `ric_data`（隔一个标准差） | 约 **0.69 米** | 231 维混在 941 维里被平均稀释 |

只修其中一个，另一个仍然是米级误差（实测：只换真值根 → 剩 1.46 米；只换真值关节位置 → 剩 1.16 米）。

### 四个方案，一句话版本

| 方案 | 一句话 | 改网络？ | 重训？ | 推荐度 |
|---|---|---|---|---|
| **A 关节位置损失** | 还原成米制关节，直接罚米 | 否 | 是 | ★★★★★ |
| **B 根积分 + ric 原尺度** | 只罚漂移的根轨迹和未归一化的关节位置 | 否 | 是 | ★★★★☆ |
| **C 加大根和 ric 权重** | 仍在归一化空间，只调系数 | 否 | 是 | ★★☆☆☆ |
| **D 改表示** | 根直接预测位置，不再积分速度 | 是 | 是 | ★☆☆☆☆（现阶段） |

**建议先做 A**。它不是最省事的，但只有它同时对齐"训练目标"和"验收指标"。

## 二、诊断证据（为什么确定是 E1 + E2）

### 2.1 先排除评测本身有问题

| 检查 | 结果 | 结论 |
|---|---|---|
| `global → local → global` 恒等反变换 | 关节 MAE **4.3e-8 米** | 坐标链闭合，不是评测换算错 |
| 原始往返（`inverse` 还原输入） | **1.6e-7 米** | 官方自校验门槛 0.03 米，通过 |
| local 与 global 两条还原路径对比 | 差异 **1.4e-7 米** | 两条路径等价，任选其一都可信 |

### 2.2 误差不是被单条坏样本拉高的

> 统一口径清单（8 条固定 clip、64 帧）。

| 统计量 | 数值 |
|---|---|
| 逐条平均关节距离 | 44.1 / 94.1 / 96.2 / 106.7 / 107.7 / 142.3 / 151.5 / **631.1** 厘米 |
| 中位数 | **107.24 厘米** |
| 最小 / 最大 | 44.09 / 631.11 厘米 |
| 最差单条 | `frog_jump_003__A360.bvh` |

7 条落在 44–152 厘米，只有 1 条达到 631 厘米。**中位数 107 cm 说明这不是一条坏样本造成的**，而是普遍现象；但最大值也提示存在离群样本，方案 A 的损失必须用 SmoothL1/Huber 而非 MSE，否则会被这一条主导。

### 2.3 分组替换实验（把真值填回某一组，看误差剩多少）

> 统一口径复测（8 条固定 clip、64 帧、传 `init_heading_info` + `ric_data`、自校验 0.000000 m）。

| 填回真值的组 | 平均关节距离 | 位置 RMSE | 根 | 非根 | p95 |
|---|---|---|---|---|---|
| 不填（模型重建） | **171.71 cm** | 103.51 cm | 115.59 | 172.44 | 243.23 |
| 只填**根** | 145.66 cm | 86.91 cm | **0.00** | 147.55 | 182.63 |
| 只填 **`ric_data`** | 115.59 cm | 83.23 cm | 115.59 | 115.59 | 205.00 |

**两条独立结论**：

1. **根的问题可以完全消除**：填回真值根后，根的误差精确归零，但非根仍有 147.55 cm → 身体自己就错。
2. **身体的问题也可以单独消除**：填回真值 `ric_data` 后，所有关节都降到 115.59 cm，而这 115.59 cm 恰好等于**根误差本身**（根错了会平移所有关节）→ 说明身体相对位置对了，只剩根在错。

**两组数字不能相加**：1.93 米（根漂移）+ 1.16 米（身体）≠ 1.72 米。因为填回一组后，另一组的误差分布也变了。表中每一行是**独立对照**，不是误差分解。

**另需说明**：朝向（`global_rot_data`）、局部速度、脚接触换成真值时，该口径下的位置指标不变——因为 `joint_positions_from="ric_data"` 的关节位置只由"根轨迹 + `ric_data`"决定。所以朝向重建质量在这个指标里**完全不可见**，这是评测口径的局限，第 6 节会列为已知限制。

### 2.4 根轨迹是怎么漂的

> 本节数字来自**统一口径**复测（`D:\tmp\diagnose_canonical.py`，8 条固定 clip、64 帧、全部传 `init_heading_info` + `ric_data`、自校验 0.000000 m）。此前版本中"1.9 米"等数字混用了未传 heading 的路径，已更正。

| 指标 | 数值 |
|---|---|
| 8 条平均末帧水平漂移 | **193.39 厘米** |
| 逐条漂移 | 1.4 / **1256.2** / 90.0 / 85.2 / 19.2 / 60.5 / 0.2 / 34.5 厘米 |
| 根速度平均绝对误差 | **4.4219 m/s** |

第 0 帧为 0、随后累积 → 这是**速度积分**的特征，不是位置偏移。单条 clip 之间差异极大（0.2 cm 到 12.6 m），说明它不是系统性偏移，而是**逐样本的速度预测错误**。

| 量（示例样本） | 真值 | 预测 |
|---|---|---|
| 水平速度（X, Z） | (-0.28, **2.55**) m/s | (0.11, **-0.81**) m/s |

方向和大小都错。64 帧 = 0.53 秒，速度差 4.4 m/s 积出来正好是米级。

**这里必须提醒一处此前的误判**：单条 clip 上曾测得"积分只漂移 15 cm"，据此一度认为根漂移被高估。那是第 0 条样本（漂移 1.4 cm）的孤立结果，不能代表整体。8 条平均是 193.39 厘米，**根漂移仍是主因之一**。

### 2.5 一个必须说清楚的坑：根高度恒为 0

`local` 表示的第 4 个根通道（`global_root_y`）统计 **std = 0.0**，真值和预测都是 0。即这批数据里根高度这一维**完全没有信息**。

这意味着：**不要**把"根高度学不会"当成误差来源。文中所有 Y 方向误差都来自 `ric_data`（把 `ric_data` 换成真值后 Y 误差变成 0），与根高度无关。

### 2.6 为什么 loss 0.36 可以和 1.7 米共存

| 量 | 数值 |
|---|---|
| 训练损失 | 941 维归一化特征的 **平均** SmoothL1 ≈ 0.36 |
| `ric_data` 归一化误差 | ≈ 1.05 → 乘自己的 std → **约 0.69 米** |
| 根速度归一化误差 | 0.21 → 乘 std（10–17）→ 两个速度通道分别约 **3.4 / 4.5 m/s** |
| 根在总额失中的权重 | **4/941 ≈ 0.4%** |

SmoothL1 在误差 > 1 之后变成线性，梯度不再随误差增大；941 维再平均一次，单组的米级误差就被摊平了。**继续加训练步数不会把 1 米变成厘米**，必须改损失。

## 三、四个方案详解

### 方案 A：还原到关节位置后直接罚米制误差

**核心思路**：既然验收指标是"米制关节误差"，就让训练损失也看这个量。

**实现位置**：`training/models/vqvae/motion_vqvae.py` 的 `loss()` 中，复用训练里已经算过的 `pred_joints_output`（现有代码为算脚滑已经调用了 `inverse`，见 L265–277），取出 `posed_joints`，与真值关节位置算 SmoothL1 或 MSE。

**可行性已实测**：

| 检查 | 结果 |
|---|---|
| 关节位置对 `recon` 可导 | ✅ `requires_grad=True` |
| 梯度是否有限 | ✅ 有限，非零元素占 **24.87%** |
| `inverse` 前向（64 帧，预热后中位） | **4.25 ms** |
| 反向（预热后中位） | **5.32 ms** |
| bs=4 每步额外开销估算 | 约 **20–40 ms** |

**注意**：这个方案有一个天然的便宜路径——现有代码**已经**在算 `inverse` 拿脚滑（`l_skate_contact`），只是没把关节位置拿去算损失。所以增量成本可能远低于独立实现。

**但这里有一个必须先解决的技术障碍（实测发现）**：

现有 `l_skate_contact` 与 `l_joint_vel` 调用 `inverse` 时**没有传 `init_heading_info`**（`motion_vqvae.py` L265–277 与 L306–312）。而推导出的根朝向依赖这个信息。诊断脚本里对比过：不传 `init_heading_info` 时，根位置的朝向还原不了，关节位置会出现**刚体旋转式的整体偏移**（历史上曾观测到 Kabsch 对齐能把 143.94 cm 降到 19.66 cm，旋转矩阵接近绕 Z 轴 180°）。

因此方案 A 落地时必须：

| 要做的事 | 原因 |
|---|---|
| 训练时也传 `init_heading_info` | 否则用来算损失的"关节位置"本身就带固定旋转偏差，罚了也罚错 |
| 或者改用"局部坐标下的关节位置"做损失 | 绕开朝向依赖，但需额外定义 |

**这一条如果不处理，方案 A 会训练出一个"朝向被人为旋转 180° 仍判为正确"的模型。** 这是本方案最大的隐藏风险，必须在动手前确认。

#### 0b 已实测：风险确认存在，且比预想更麻烦

固定同一 clip、同一朝向，只切换是否传 `init_heading_info`：

| 口径 | pred vs gt 关节 MAE |
|---|---|
| 不传 `init_heading_info`（训练路径现状） | **64.24 cm** |
| 传 `init_heading_info`（评测路径） | **42.36 cm** |
| 两种口径下 gt 自身之差 | **32.60 cm** |

三条结论：

1. **偏差真实存在**：同一段动作，只因为不传朝向信息，还原出的关节位置就差 32.60 cm。
2. **不是纯刚性旋转**：去掉质心后形状仍差 31.82 cm，说明缺 heading 时整段动作的相对位置也被错误累积旋转，不能靠事后对齐修掉。
3. **现有 `l_joint_vel` 侥幸没事**：它罚的是相邻帧差分，系统偏移被差掉大半；但方案 A 罚绝对位置，偏差会直接进损失。

更要紧的是：训练里 `change_first_heading` 用的是**随机角度**，且该函数**不返回**任何朝向信息（已核实 `global_root_local_body.py` 与 `motion_vqvae.py` 均无相关返回）。因此"补传 heading"不是补一个参数，而是要改表示层函数的返回值。

**据此方案 A 拆成两种实现**：

| 变体 | 做法 | 改动面 | 风险 |
|---|---|---|---|
| **A1** | 让 `change_first_heading` 返回朝向信息，训练时透传到 `loss()`，三处 `inverse` 都带上 | 表示层 + 损失层 + 调用链 | 改动扩大，但脚滑与 joint_vel 也一并修正 |
| **A2** | 关节位置损失改在 **local 空间**（无 heading 依赖）计算，不碰全局还原 | 仅损失层 | 绕开朝向，但损失与"世界空间米制误差"不完全等价 |
| A3 | 照抄现有调用 | 无 | ❌ **会罚错目标，禁止** |

**A2 需要额外验证**：local 空间的关节位置是否足以约束 E1（根漂移）。因为根轨迹在世界空间累积，local 表达可能看不到漂移——这一点尚未验证，不能假设成立。

**优点**
- 训练目标和验收指标完全对齐，不存在"指标好看但误差大"的缝隙
- 同时覆盖 E1 和 E2（因为它看的是最终位置）
- 不改网络结构，不改表示，checkpoint 兼容

**缺点**
- 米制误差量纲大（厘米到米级），**必须仔细调系数**，否则会压垮重建损失
- 需要 `SmoothL1` 或 Huber，直接 MSE 容易被离群帧主导
- 每步多一次反向

**风险与缓解**

| 风险 | 缓解 |
|---|---|
| 系数过大导致重建崩坏 | 从 0.01 起，看 `l_recons_pose` 是否稳定 |
| 离群帧（如 frog_jump 6.3 米）主导梯度 | 用 SmoothL1/Huber 而非 MSE |
| 与 `joint_vel_loss` 重复惩罚 | `joint_vel_loss_coeff` 目前是 2.0，可能需要下调 |

---

### 方案 B：根积分 + `ric_data` 原尺度

**核心思路**：不还原到关节，只针对两个已确认的病灶分别加损失。

**两部分**
1. **根轨迹损失**：对归一化的根通道反归一化 → `compute_root_pos_and_rot` → 得到 `cumsum` 后的根位置 → 与真值根位置算误差。
2. **`ric_data` 原尺度损失**：把 `ric_data` 反归一化回米，再算误差，避免被归一化尺度和 941 维平均稀释。

**可行性已实测**：

| 检查 | 结果 |
|---|---|
| 根轨迹可导 | ✅ `requires_grad=True` |
| 梯度有限 | ✅ 有限 |
| 梯度非零元素占 **0.21%** | ✅ 正好只命中根通道，不污染其他维度 |
| 根前向（64 帧，中位） | **2.70 ms** |
| 根反向（中位） | **1.06 ms** |

**优点**
- 比 A 轻（反向 1 ms vs 5.3 ms）
- 精准打击已确认的两个病灶，可解释性强
- 不改网络，checkpoint 兼容

**缺点**
- **不覆盖 E2 之外的身体误差**：如果身体误差不只是 `ric_data` 的尺度问题，而是更高阶的形态错误，这个方案看不到
- 仍然没对齐最终验收指标（它是 proxy）
- 两个新系数要调

**风险与缓解**

| 风险 | 缓解 |
|---|---|
| 只修根不修身体，指标看着好但关节仍错 | 同时做 A，或至少在评测里拆开报告根/非根 |
| 根位置损失在长窗口主导梯度 | 按帧归一（除以窗口长度） |

---

### 方案 C：加大根和 `ric_data` 的权重（最小改动）

**核心思路**：不动结构，只调现有系数。

**现状**（`motionweaver_vqvae.yaml`）：

| 系数 | 当前值 |
|---|---|
| `global_root_loss_coeff` | 0.5 |
| `local_root_loss_coeff` | 0.5 |
| `commit_loss_coeff` | 0.02 |
| `skate_contact_loss_coeff` | 0.01 |
| `joint_vel_loss_coeff` | 2.0 |

**为什么它治不了根因**：这些系数作用的仍然是**归一化后的单帧特征**。根速度预测错 3–4 m/s 时，它的归一化误差只有 0.21，**再乘 10 倍系数，梯度信号依旧建立在"单帧特征差"上，而不是"积分后的位置差"**。积分误差靠加权是补不回来的。

**优点**：改一行、零代码、零风险探测成本。
**缺点**：机制上不解决 E1；对 E2 有部分作用（相当于给 `ric_data` 加权），但依然是归一化空间。

**结论**：只作为**对照实验**保留，不作为主方案。

---

### 方案 D：改表示，根直接预测位置

**核心思路**：把根表示从"旋转速度 + 线速度（需积分）"改成"直接给位置"，从机制上消除积分漂移。

**为什么现在不考虑**：

| 障碍 | 说明 |
|---|---|
| 需要改 `DualRootGlobalJoints` 表示层 | 影响数据统计量、checkpoint、ONNX 导出、UE 端 |
| 全部已有权重失效 | `tok_BC120`、`entropy_20k` 等都不能再加载 |
| 与上游官方表示分叉 | 官方 `GlobalRootGlobalJoints` 就是速度表示，改了就难以对比 |
| 上游推理侧要同步改 | UE 集成假设了当前表示 |

**优点**（如果做）：从根上消除漂移，理论上最干净。
**缺点**：改动面覆盖数据、训练、导出、引擎四层，现阶段成本远超收益。

## 六、必须保留的局限

1. **8 段样本量小**，且全部来自 B/C 场景。结论不能外推到 A/D 场景。
