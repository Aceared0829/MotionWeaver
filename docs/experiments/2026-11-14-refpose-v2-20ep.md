## 问题与方案

- 研究问题：在 full_release_v2 全量数据（71,128 条 clip / 2,490,713 个窗口）上，把 ReferenceGuidedPose 训练到 20 epoch，验证 RMSE 是否仍随 epoch 单调改善，以及四档硬参考的相对次序是否保持。
- 本次操作：以 `tools/train_reference_pose.py` 训练 20 epoch；训练完成后用 `tools/evaluate_reference_pose.py` 在 test 分区四档硬参考评估，并用 `training/evaluation/evaluate_conditioned_baselines_parallel.py` 跑 hold / linear_reference 非学习基线，最后 `tools/merge_evaluation_report.py` 合并。
- 对照组：无学习基线（hold、linear_reference 插值），同一选窗口径（每条 clip 取中心窗口，per_clip=1）。
- 固定条件：契约、骨架、划分、种子与超参全部固定；唯一变化因素是训练 epoch 数（与 ep14 的中途检查点对照）。
- 预定评价指标：非锚点关节逐关节欧氏距离 RMSE（cm），先按 clip 求值再等权平均；辅助指标为接触期脚滑倍数。

## 结论与论文使用边界

- **直接测得：** 20 epoch 全量训练在 test 分区四档硬参考上分别为 5.59 / 3.50 / 3.04 / 2.46 cm，相对 Lerp 基线 2.81× / 1.99× / 2.31× / 1.40×；验证集 RMSE 从 ep14 的 4.25 cm 降到 ep19 的 4.05 cm，曲线在 ep17 后趋于平缓（ep18 4.06、ep19 4.05），说明余弦退火末端收益已接近饱和。
- **基于结果的推断：** ep14 → ep19 的改善幅度（0.20–0.27 cm）小于 ep10 → ep14（约 0.4 cm），继续延长 epoch 的边际收益很小；中间+末帧档的脚滑（逐 clip 均值）同时从 15.25× 降到 13.19×，提示位置精度改善没有以牺牲接触一致性为代价。
- **尚未验证、不能据此宣称：** 未做 UE 内蒙皮、IK、碰撞与连续玩家控制的验证；Root 轨迹是 oracle，不代表玩家或 CMC 的轨迹误差；未做人工视觉复核，2.46 cm 是否「看起来能播放」没有证据；脚滑仍远高于 1.0，且不同档位间的脚滑差异（逐 clip 均值 10.0–13.2×）尚无机制解释。
- 与上游/先前实验的口径差异（三条差异 + 一条不可补测，缺一条就会误判）：
  1. **契约不同**：本次用 full_release_v2 重建契约（无封版 freeze_manifest）。v3 用 full-v1-f32：71,127 clip / train 1,988,285 / val 245,232 窗口；本次 71,128 clip / 1,992,148 / 247,979。
  2. **test 集不同**：v3 test 6,935 clip / 257,171 窗口，本次 7,046 clip / 250,586 窗口。Lerp 基线 16.64–3.66 vs 15.70–3.45，基线数值不同即证明选窗不同，故四档 ±0.3 cm 的差距有一部分来自测试集差异。
  3. **脚滑分母不同**：本次源动作接触脚速 0.0311 m/s，v3 记录 0.0261 m/s，差 19%。用各自分母看，本次 pooled 6.62–9.00 与 v3 的 6.9–8.7 基本持平；强行统一到 v3 分母则是 7.87–10.70，全面偏高 14–23%。**脚滑无可比性，不能据此断言退化。**
  4. v3 封盘权重 `6d10d358…ed55ffc` 本机不存在（`model_weight` 目录无、`runs/refpose_71k_linux` 为空），因此无法把 v3 拉回同一套 test 集重跑，上面三条差异无法通过补测消除。
- 后续：若要继续压低误差，应改数据或损失（例如接触权重、Root 条件方式），而不是单纯加 epoch；脚滑差距按既有决策交 UE 端 Two-Bone IK / Foot Locking / 步幅匹配补齐。
