## 问题与方案

- 研究问题：20 epoch 的验证 RMSE 在 ep17 后趋于平缓（4.07 / 4.06 / 4.05），这是**真的饱和**还是**余弦退火末端 LR 太小**导致的假平？如果把余弦周期整体拉长到 30 epoch、让同一进度位置还有 7.5e-5 的 LR，误差还能不能继续降？
- 本次操作：从 `runs/refpose_v2_20ep/last.pt`（ep19，val 4.05）续训，`--epochs 30`，只补跑 ep20–ep29。
- 对照组：上一轮的 ep19（20 epoch 终态）。**同契约、同 test 集、同选窗口径、同源动作脚速分母**（`source_contact_foot_speed_mps` 两轮均为 0.03105058），唯一变化因素是 epoch 数与随之变化的 LR 日程。这是一次干净的单变量对照。
- 预定评价指标：验证集 RMSE 逐 epoch 曲线；test 四档硬参考 RMSE（cm）、中位数、最差 clip、相对 Lerp 倍数、脚滑倍数。

- 生效配置：与 20ep 轮完全相同（batch 256、width 256、AdamW lr 3e-4 / wd 0.01、contact_weight 0.4、chunk 16、workers 8、bf16 autocast、grad clip 1.0），只把 `--epochs` 从 20 改成 30。因此 `T_max` 从 155,620 步变为 233,430 步。
- **续训的 LR 衔接（本次的核心机制）**：余弦周期拉长后不能直接搬旧调度器状态——`load_state_dict` 会把 `T_max` 覆盖回 155,620，余弦从 -1 折返、LR 沿原路回升。实际做法是保持「同一进度位置」：已跑 155,620 步在 30 epoch 的新余弦上对应 **7.50e-05**（日志确认：`续训：last.pt epoch 20 起，已跑 155620 步，lr=7.50e-05`），与余弦闭式解逐位相同。这个值高于 20 epoch 终点处的 0，是一次「小幅重新升温」，之后的退火曲线比原来更平缓（10 个 epoch 从 7.50e-05 降到 1.2e-11）。
- 软件与设备：Python 3.14 venv、PyTorch 2.15.0 (CUDA)、RTX 4070 Laptop 8 GB、30 GB RAM + 46 GB swap。
- 数据与划分：`/home/acear/MotionWeaverData/full_release_v2`（71,128 clip / 2,490,713 窗口），train 1,992,148 / validation 247,979 / test 250,586 窗口，test 7,046 clip。每 epoch 7,781 步，30 epoch 共 233,430 步；本次实跑 ep20–ep29 共 77,810 步。
- 条件输入与标签边界：Root 轨迹取原动作（oracle）；硬参考帧直接取自目标帧。

## 结果与证据

### 验证集 RMSE 曲线（cm）

ep19（续训起点）4.05 → ep20 **4.30** → ep21 4.16 → ep22 4.11 → ep23 4.04 → ep24 4.02 → ep25 3.97 → ep26 3.95 → ep27 3.93 → ep28 3.92 → **ep29 3.91**（全程最优，已存 best.pt）

- **ep20 先升后降不是噪声**：LR 从 20 epoch 终点处的 0 跳回 7.50e-05，模型被推离已收敛的位置，一个 epoch 内从 4.05 退到 4.30；随后 9 个 epoch 单调下降到 3.91。这说明 20ep 的「平缓」里有一部分确实是 LR 太小造成的。
- 但收益很薄：ep20–ep29 这 10 个 epoch（77,810 步，39.9 min）只再降了 **0.14 cm**（4.05 → 3.91），而 ep0→ep10 一条曲线自己就降了 3.7 cm。

## 结论与论文使用边界

- **直接测得：** 从 20 epoch 续到 30 epoch，验证 RMSE 4.05 → 3.91 cm（−0.14）；test 四档 5.59/3.50/3.04/2.46 → 5.40/3.39/2.94/2.38 cm（−0.19/−0.11/−0.10/−0.08），相对 Lerp 倍数升到 2.91×/2.05×/2.39×/1.45×。脚滑两个口径都小幅下降。代价是 39.9 min 额外训练。
- **基于结果的推断：** 20 epoch 末端的平缓不完全是饱和，也有一半是余弦退火把 LR 压到 0 造成的；拉长周期确实还能再挤出一点。但边际收益已经很低：10 个 epoch 换 0.08–0.19 cm，且收益随参考强度递减、在中末双参考档的最差 clip 上还是负的。**要再降误差，投入应该转向上游数据或损失设计，而不是继续加 epoch。**
- **尚未验证、不能据此宣称：** 未做 UE 内蒙皮/IK/碰撞与连续玩家控制验证；Root 轨迹是 oracle，不代表玩家或 CMC 轨迹误差；未做人工视觉复核，「2.38 cm 是否看起来能播放」没有证据；脚滑仍远高于 1.0。
- 与上一轮的口径关系：**这两轮之间是可比的**（同契约、同 test 集、同选窗口径、同脚滑分母），与 v3 封盘仍然不可比（理由见 [20ep 记录](2026-11-14-refpose-v2-20ep.md) 的四条口径差异，本机缺 v3 权重无法消除）。
- 后续：脚滑按既有决策交 UE 端 Two-Bone IK / Foot Locking / 步幅匹配；若要继续提升精度，应改数据（更长的历史、更细的接触标注）或损失权重，而不是单纯加 epoch。
