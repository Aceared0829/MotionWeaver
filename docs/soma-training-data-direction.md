## 已确认的推理与玩法分工

用户确认普通 Locomotion 无需跑酷代理，主要根据当前身体姿态、站立/蹲下状态及基础姿态参考执行。跑酷代理用于复杂跳跃、翻越、攀爬等任务，在玩家满足启动位置并按住跑酷按键时提供轨迹箭头、语义标签与硬参考姿态。两个入口共用已验收的 SOMA uniform 目标骨架，具体网络是否共用主干或分头不在本阶段确定。

| 项目 | 普通 Locomotion | 复杂跑酷任务 |
| --- | --- | --- |
| 启动方式 | 角色常规移动与姿态控制，直接执行 | 满足代理启动条件后执行任务 |
| 基础输入 | 当前/历史姿态、实际运动状态、站蹲状态、基础姿态参考 | 同样需要基础输入 |
| 移动意图 | 玩家/AI 和运动组件提供速度、方向等控制意图 | 代理提供轨迹、朝向、经过点与终点 |
| 姿态参考 | 站姿、蹲姿等基础参考，不要求每个窗口给未来关键帧 | 指定阶段/时刻的全身或局部姿态、手脚目标与约束掩码 |
| 语义信息 | 站蹲、步态等必要状态，不强制提供跑酷任务标签 | 动作类型、动作阶段、约束意图 |
| 运行时 Root | 角色运动组件负责实际位移与碰撞，模型生成相对姿态 | 代理规划与角色运动组件执行配合，实际状态反馈给生成模型 |
| 结束方式 | 持续响应常规控制 | 完成任务后接回常规移动或进入下一任务 |

这里的速度/方向是普通角色移动已有的输入，不要求增加代理。当前站蹲状态、玩家请求的站蹲状态，以及引擎是否允许起身是不同信息；数据中可从动作观察到的姿态状态，不能代替玩家请求或引擎碰撞批准。

动作类别与运行模式分开记录。一个片段含跳跃或腾空，不足以证明它运行时必须经过代理；同一动作也可用于不同条件任务。数据分流先生成候选并审核，运行时模式由控制器与任务状态明确选择。

## 跑酷代理的职责与演进

代理任务描述包含启动范围、接近方向/速度、按键与角色状态条件，轨迹及朝向提示，动作语义与阶段，参考姿态及关节掩码，手脚接触/到达目标，以及完成、退出和接续条件。轨迹提示是计划，实际运动需要通过角色运动与碰撞执行；模型、代理和运动组件不得重复叠加角色位移。

实施顺序为手工代理、静态环境分析生成候选代理、动态环境目标跟踪与重规划。手工和自动来源使用同一任务条件格式。动态平台上的抓握/落点应绑定目标组件的局部坐标及更新机制；动作阶段决定目标失效、松键或退出时的处理，避免在空中机械中断。自动代理只在可达性与碰撞检查通过后执行，动态环境能力属于后续开发目标。

上游负责提供推理时实际可获得的任务条件；生成模型补全条件之间的连续运动。语义标签用于指定动作意图，关键姿态输入用于引导，硬约束还必须有输出约束机制和误差验收。Root 相对的手部姿态需要与同一时刻的 Root 变换一致，才能满足场景中的抓握位置。

## 三种参考信息的区别

1. **参考骨架**：已冻结的 `soma_uniform_v1` 局部参考 TRS、拓扑和语义角色，用于统一数据与空间。它不是运行时的站立或蹲下指令。
2. **基础姿态参考**：普通 Locomotion 使用的站姿、蹲姿或风格原型，可以作为姿态条件。具体约束强度另行确定，不默认等同于未来某时刻必须精确满足的全身关键帧。
3. **任务硬参考**：跑酷代理在指定时刻/阶段提供的全身或局部关节姿态与接触目标，需要参考时刻、骨骼掩码、空间定义及可验证的输出约束。

基础姿态可建立一个小型版本化参考库，逐样本引用相应参考，不必复制一份完整姿态。普通样本的任务硬参考允许缺省，跑酷样本只暴露明确提供的约束；未提供的未来姿态仍只作为监督目标。

## 本轮真实 SOMA 样本检查

检查了 `soma_uniform/bvh/240918/body_check_001__A548.bvh`。78 个节点的名称与父索引和参考文件一致，最大参考偏移差约 0.0000103 cm；原生导入、30 FPS 标准化和共享骨架文件往返通过。这只验证该样本，不代表全库的骨架兼容和质量已通过。

该样本的 Root 六个通道全部静止，Hips 六个通道有运动。因此统一训练轨迹不能机械采用 SOMA Root 节点的数值；需要从 Hips 制定版本化的水平轨迹、朝向和骨盆垂直运动分工，并验证跳跃与转向。UEFN 的来源 Root 轨道仍保留作审计，新训练出口按共同语义转换。

该 BVH 声明的 Frame Time 对应约 120.0048 FPS（十进制精度近似），按真实时间标准化到 30 FPS 得到 942 帧。后续需要明确保留声明时间还是按来源名义 120 FPS 校准，并记录策略；不能只改 FPS 标签，或用全局宽松末帧容差掩盖长片段累积漂移。

## 处理链路

```text
SOMA uniform / SOMA proportional / 外部通用动画 ─┐
                                               ├→ 原生运动 → 空间与时间标准化
UEFN 原生导出（保留来源骨架）───────────────────┘
    → 固定 SOMA 目标骨架适配
    → 完整性检查与来源/目标审核
    → 训练表示、统计量与 Manifest
    → 模型训练
```

SOMA uniform 是同骨架基线候选；UEFN→SOMA 是真正的跨骨架转换。UEFN 中独有的 Twist/武器骨不硬塞进目标身体；SOMA 中缺少来源监督的面部、具名末端及手指细节必须说明保持参考姿态或规则生成的策略。生成值及对应损失策略应由训练消费者实际使用，不能仅靠元数据声明质量通过。

独立 Root 与身体姿态继续分开，但先核对 SOMA Root/Hips 的语义。BVH Hips 的绝对平移需显式配置，不能重复加参考 OFFSET；坐标单位和轴基由来源配置给出，不把首帧当参考姿态，也不假设所有来源的根节点都是 Actor 世界轨迹。

## 从推理条件反推数据处理

### 共用动作数据与独立任务索引

两条推理路径共用 raw、固定 SOMA 目标运动、来源/映射身份、质量检查和数据划分。普通 Locomotion 与跑酷各建立条件窗口索引，引用同一份动作数据；不先复制成两套物理数据集，也不预先要求拆成两个模型。

| 数据组 | 需要保留或建立的内容 | 来源与可用性 |
| --- | --- | --- |
| 动作身份 | 来源片段、动作家族/会话、镜像/派生关系、文件哈希、目标签名、映射版本、真实有效帧 | 原始文件、官方元数据和处理报告 |
| 基础运动 | 全身局部 TRS、身体与 Root 参考关系、骨盆/手/脚轨迹、速度、朝向变化 | 可从骨骼轨道计算；Root 派生规则尚待固定 |
| 普通姿态状态 | 当前/历史站蹲状态、站蹲过渡区间、基础姿态参考 ID | 来源标签和动作几何生成候选，人工验证典型边界 |
| 跑酷语义与阶段 | 动作类型、起跳/支撑/翻越/落地等阶段、事件时刻 | 复用文本/动作标签，补充小样本阶段标注；片段标签不直接当逐帧真值 |
| 接触候选 | 脚/手轨迹、速度与稳定区间，可能的支撑/腾空区间 | 从动作导出的启发式结果；不等于真实碰撞或场景接触 |
| 任务参考 | 参考时刻、骨骼掩码、姿态、目标空间、参考来源 | 离线可从明确选定的真实帧构造；运行时由代理/模板/检索/规划提供 |
| 场景目标 | 障碍物、抓握点、落点、目标组件局部坐标与动态更新 | 当前原生动作文件未提供的内容标记未知；不能由手脚位置直接伪造 |
| 引擎控制状态 | 玩家请求、实际站蹲批准、可起身检查、任务启动/退出、实际 Root 反馈 | 后续 UE 运行记录；离线来源没有这些信息时保持不可用 |

每个来源标签或派生结果记录来源、方法版本和 `unknown/provisional/verified` 状态。确有校准依据时才增加数值置信度。未知接触、场景目标或玩家请求不能编码成确定的 false/零值；输入掩码明确区分未提供条件与真实零值。

参考有效性和监督有效性分开：SOMA 原始关节是否有真实运动、UEFN→SOMA 的关节是否由补全得到，属于监督来源；推理有没有提供该关节的参考约束，属于条件可见性。两个掩码不能共用。

站蹲候选先结合来源标签、骨盆相对双脚的高度及髋/膝弯曲程度，不只按骨盆的绝对高度分类；转向、跳跃、登高、跪姿和混合状态作为重点复核项。基础站姿/蹲姿参考从已复核的代表姿态中建立，不将目标骨架的 T 形参考姿态当成运行时站姿。

手脚轨迹先在保留完整运动的录制空间中计算；Root 分解后再验证重合成一致性，避免把 Root 相对脚速误当完整移动下的脚速。脚速低、手部稳定或高度低只产生接触候选，真实地面/墙面未知时保留未知状态。阶段与关键姿态先结合动作标签和实际轨迹挑选代表帧，均匀抽帧可以用于条件训练对照，但不能声称自动获得了起跳、撑手或落地事件真值。

### 两类训练任务的可见条件

普通 Locomotion 样本以真实历史/当前姿态和运动状态为基础，加入当前姿态状态、可用的目标姿态条件及基础姿态参考。离线从后续动作反推的目标站蹲或速度须标为代理条件；后续采集真实玩家/运动组件日志后再验证在线一致性。普通任务允许没有未来硬参考，不为适配跑酷接口而强制暴露未来关键帧。

跑酷样本在同样基础上增加明确的任务语义、阶段/事件、控制轨迹和选定的硬参考。训练时可以从完整动作抽取少量参考帧，但未选未来帧只能作为监督。评估分别记录使用源动作真值条件、使用可部署的代理条件、以及没有参考条件的结果，不能把理想条件结果当成在线代理性能。

条件统一使用已固定的 SOMA 目标坐标及引用的 Root 空间。引擎目标可保留世界或组件局部坐标的原始身份，经显式转换后送入模型，避免将世界抓握点与 Root 相对姿态混合。具体未来窗口长度、FPS、Root 派生和条件时间表达仍待讨论，不继承旧契约的 24 帧/79 骨设置作为新目标默认值。

### Root 与时间规则的后续验证

Root 表示方案要同时服务普通移动和跑酷任务，最终必须能与身体姿态合成恢复动作。普通站蹲样本重点检查骨盆下降与步态起伏；跳跃、翻越和攀爬样本检查腾空、支撑、整体登高和落地缓冲。仅凭骨盆曲线无法唯一恢复真实 Actor Root；结合手脚运动、标签与阶段得到的分解仍须声明为派生规则，保留来源轨道和对照结果。

代理给出的运动轨迹是运行时控制输入，数据中从完整动作提取的轨迹是训练/离线标注，两者在来源上明确区分。这个分工允许普通移动直接使用控制器，不要求先创建代理。当前已固定离线 Root 代理 v1（Hips X/Z、Y=0、有效人体朝向，所有高度留在身体）；它不是实际 Actor Root。UE 垂直运动分工和接触修正另行验证。

时间方面先核对不同来源的声明时间、名义采样率与长片段累计差异，再决定是否校准到名义 120 FPS 及训练重采样策略。基础姿态参考、事件时刻、硬参考和监督目标必须在同一时间轴上对齐。保持来源时间身份，末帧保持与真实有效帧分开，避免将补齐帧当事件或接触真值。

### 数据划分与验收

先按来源动作/录制会话确定分区，再派生两类任务窗口。左右镜像、重采样、裁剪、uniform/proportional/G1 同源版本、以及有可靠同源关系的跨骨架转换结果继承同一分区。普通与跑酷索引共用分区，不用同一动作的不同条件版本跨训练和测试。现有 UEFN 源数据与 SOMA 原始动作没有已确认的一一配对表，不伪造配对关系。

数据验收分四层：骨架/轨道/时间完整性；必要来源语义及自动候选抽检；条件可见性及参考监督分离；来源与结果的动作质量。全库精细语义和逐帧人工标注不作为统一门槛。硬参考还需验收指定节点在约定空间的误差与参考前后的连续性，满足关键帧本身不能替代骨长、手脚接触和碰撞验收。线上移动、代理可达性与动态目标能力另在 UE 中验证。

## 实施顺序

1. 已恢复原生数据处理与审核，完成 1,970 条 UE 动画回读；SOMA 目标快照的技术和人工验收已通过。

3. 在这些样本上展示骨盆/手脚轨迹、已有标签、站蹲/阶段和接触候选；对照 Root/Hips 分解与时间策略。先人工复核代表样本，再冻结这两项规则。
4. 建立小型站姿/蹲姿基础参考库，以及独立的跑酷关键姿态候选。用共用运动数据建立普通和跑酷两类条件索引，验证可见条件、未知掩码、来源身份与分区一致性。
5. 选择约 30 条 UE 动作，配置 UEFN→SOMA 关节/链映射、参考校正、目标骨长与位移尺度；做来源和目标的同步对照。缺失监督和规则生成的关节显式标记。
6. 适配训练准备逻辑和模型骨架/特征维度，重新计算训练分区统计量，评估 Tokenizer 与旧权重兼容性。训练与数据扩量在对应验证通过后开展。
7. 运行时先验证无需代理的普通移动，再接手工跑酷代理，后续扩展静态与动态环境自动代理；这些能力不能由离线动作回读或真值 Root 条件试验代替验收。

原始动作、左右镜像和派生片段必须按来源动作/录制会话分组划分，继承同一个 train/validation/test 分区；uniform、proportional、G1 的同源记录也不能跨分区。现有 UEFN 原生验收记录保留，转换后的 SOMA 结果绑定新输出哈希、目标快照和映射版本，单独验收。
